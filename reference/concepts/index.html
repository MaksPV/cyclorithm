    Концепты¶

    Что означает каждая сущность расписания и как она записывается. Порядок — от простых ячеек к целому файлу. Термины — в глоссарии

    Точка point¶

    Место, где происходят действия: парк, аэропорт, звонок. Самый простой вариант — только список допустимых действий actions:

    point DEPOT {
  actions = [depart, arrive];
}

    Список не бывает пустым: точка без действий запрещена.

    Дополнительно точка может нести атрибуты attrs — словарь, который копируется в каждое событие точки:

    point BELL {
  actions = [ring];
  attrs = {"building": "Л"};
}

    Поле attrs необязательно: без него point_attrs события пустое ({}). С ним каждое событие звонка несёт копию словаря:

    {"time": "2026-09-07T09:00:00", "action": "ring", "point": "BELL", "point_attrs": {"building": "Л"}, "action_attrs": {}}

    Поле action_attrs здесь пустое, потому что вызов без атрибутов, — про них в следующем разделе. Если словарь общий для нескольких точек, его выносят в const и ссылаются именем (attrs = CORPUS;).

    Действие action¶

    То, что происходит в точке. В выводе — поле action события. Вызывается как <ТОЧКА>.<действие>():

    0m: BELL.ring();

    Вызов может нести атрибуты {"k": v, …} — они попадают в событие полем action_attrs:

    5m: BELL.ring() {"event": "start"};

    Блок необязателен: без него action_attrs пустое. С ним событие выглядит так:

    {"time": "2026-09-07T09:05:00", "action": "ring", "point": "BELL", "point_attrs": {"building": "Л"}, "action_attrs": {"event": "start"}}

    Событие event¶

    Единица вывода — то, что произошло в конкретный момент. Собирается из пяти частей: время — момент строки, в который сработал вызов; имя действия и имя точки — из самого вызова; словарь point_attrs пришёл из точки, словарь action_attrs — из вызова. Полный вид из примера attrs.cyclo:

    {"time": "2026-09-07T09:00:00", "action": "ring", "point": "BELL", "point_attrs": {"building": "Л", "floors": 5}, "action_attrs": {"subject": "БЖД", "type": "лек", "room": "233/А", "event": "start"}}

    События складываются в массив events объекта, который выдаёт программа. Порядок и форма объекта — в формате вывода.

    Вызов invocation¶

    То, что стоит справа от двоеточия в строке. Два вида: действие точки даёт событие, вызов цикла или рутины раскрывается в строки. Все возможные формы:

    0m: DEPOT.depart();  // действие точки — даёт событие
5m: DEPOT.depart() {"fuel_used": 25};  // действие с атрибутами
6h: CITY_ROUTE();  // цикл без аргументов
9h: LESSON(LEC);  // цикл с передаваемыми в него данными
9h30m: LESSON({"subject": "САПР"});  // а можно и так
0h: MONDAY(UNIVERSITY_DAY);  // рутина — первый аргумент всегда таблица времени
0h: EXAM(DAY, LEC);  // рутина с таблицей и передаваемыми в него данными

    Длительность и смещение duration¶

    Длительность — сколько длится цикл. Пишется компонентами от крупных к мелким: недели w, сутки d, часы h, минуты m, секунды s, миллисекунды ms. Каждый компонент не более раза:

    cycle CITY_ROUTE duration = 1h20m {

    Смещение — когда внутри цикла срабатывает строка: старт объемлющего цикла плюс смещение. Отрицательное считается от конца, -0m — ровно конец:

    0m: DEPOT.depart();  // старт цикла
40m: AIRPORT.arrive();  // через 40 минут
-0m: DEPOT.arrive();  // встык к концу

    Цикл cycle¶

    Именованная цепочка строк. Сама по себе событий не порождает, выполняется только по вызову. В заголовке — необязательные параметры и длительность duration, в теле — строки <смещение>: <вызов>;. Содержимое обязано влезать в длительность: конец самой поздней строки не дальше duration, иначе ошибка cycle-overruns.

    cycle CITY_ROUTE duration = 1h20m {
  0m: DEPOT.depart();
  40m: AIRPORT.arrive();
}

    Параметры принимают данные вызова и видны в теле цикла:

    cycle LESSON(subj) duration = 1h35m {
  0m: BELL.ring() {"subject": subj.subject};
}

    Условие и момент строки at¶

    В языке реализованы условия. Если оно выполняется, то вызовы выполняются. Простейшее — один предикат:

    [weekend(at)] 12h: CITY_ROUTE(); // выполняется только по выходным

    Условия могут комбинируются.

    [hour(at) >= 7 and not weekend(at)] 10h: SHUTTLE();

    Условие вычисляется для момента строки at — абсолютного времени строки в мс: времени старта родительского цикла плюс смещение вызываемой строки.

    Повтор (repeat / fill)¶

    Одна строка запускает цикл несколько раз подряд. Сколько раз — задаёт модификатор между : и вызовом:

    10h: repeat 2 SHUTTLE();  // ровно два запуска
14h: fill until 15h SHUTTLE();  // пока помещается до 15h
19h: fill SHUTTLE();  // пока помещается до конца цикла

    repeat N — ровно N запусков, невместившаяся цепочка — ошибка. fill — сколько поместится, лишнее молча отбрасывается. Горизонт until T считается от старта объемлющего цикла, а не от строки; отрицательный until -X — от конца (duration родителя минус X).

    Условие строки проверяется для каждого запуска отдельно. Цикл SHUTTLE имеет длительность 20 минут, запуски стартуют в 10:30, 10:50 и 11:10 — третий не подходит под условие и выпадает, первые два стоят на местах:

    [hour(at) < 11] 10h30m: repeat 3 SHUTTLE();

    10:30 — рейс есть
10:50 — рейс есть
11:10 — рейса нет

    Объявления const / fun / pred¶

    Именованные кирпичики файла. const — значение: число, строка или словарь/массив. Строки и словари живут здесь:

    const MORNING = 6;
const ROOM = "233/А";
const LEC = {"subject": "БЖД", "room": ROOM};

    fun — число от аргумента, pred — условие от момента времени. Оба вызываются там, где нужно вычисление вместо литерала:

    fun rush_top(x) = x + 1;
pred commute(at) = morning(at) or evening(at);

    [hour(at) >= rush_top(MORNING)] 10h: SHUTTLE();
[commute(at)] 18h: SHUTTLE();

    Объявления — верхний уровень файла, до расписания. Системные имена (morning, weekend и весь календарь) подключать не нужно.

    Импорт use¶

    Чужие объявления подключаются первой строкой файла:

    use "libs/route_lib.cyclo";

    Путь — от директории файла. Внутри библиотеки только объявления (const, fun, pred, таблицы времени), расписания там нет.

    Таблица времени и рутина time_const / routine¶

    Пары идут в одно и то же время всю неделю. Без таблицы время каждой пары пришлось бы писать в каждом дне; с таблицей слоты объявляются один раз, а дни ссылаются метками:

    time_const UNIVERSITY_DAY duration = 21h35m {
  1st: 9h;
  2nd: 10h45m;
}
    • Объявление верхнего уровня, как const/fun/pred.
    • Импортируется через use.
    • Каждая строка обязана иметь метку. Метки — буквы, цифры и _, цифра в начале разрешена (1st); имя вида 1ms разберётся длительностью, таких имён не давать. Минус — только у длительности.

    Строка таблицы может нести вызов со стрелкой -> — фиксированное событие дня, объявленное один раз на таблицу, а не на каждый день. Такая строка выполняется при каждом применении таблицы, может иметь собственное условие:

    time_const UNIVERSITY_DAY duration = 21h35m {
  [workday(at)] lunch: 12h20m -> LUNCH();
}

    Цикл на метках — рутина, шаблон дня. Тело записывает метки вместо смещений, первый параметр — всегда таблица времени, остальные — данные, как у цикла:

    routine MONDAY(TC) {
  1st: LESSON(LEC);
}

    Вызов MONDAY(UNIVERSITY_DAY) подставляет смещения таблицы: метка 1st превращается в 9h, строки таблицы со стрелкой добавляются после строк тела. Словарь LEC — тот самый const из раздела «Объявления».

    Смена таблицы сдвигает все дни сразу: сокращённый день — та же рутина, другая таблица. Одна строка вместо переписанного дня, пары едут по новой сетке — 9:00 и 10:30:

    time_const SHORT_DAY duration = 14h35m {
  1st: 9h;
  2nd: 10h30m;
}

    Корневой цикл root_cycle¶

    Задаёт решётку стартов — когда запускаются циклы и одиночные действия. Ровно один в расписании: пара start_time + duration, где duration — период решётки. Команда run берёт окно --start/--end и накладывает на эту решётку.

    root_cycle start_time = "2026-01-09T00:00:00", duration = 24h {
  6h: CITY_ROUTE();
}

    Расписание schedule¶

    Корень файла. Связывает точки, шаблоны и корневой цикл в одно целое. Имя попадает в поле schedule вывода. Запись: schedule "Имя" { … }.

    schedule "Автобусный парк" {
  point DEPOT {
    actions = [depart, arrive];
  }
  root_cycle start_time = "2026-01-09T00:00:00", duration = 24h {
    6h: DEPOT.depart();
  }
}

    Как связаны¶

    точка point → действия actions (+ атрибуты attrs → point_attrs)
действие action → атрибуты {"k": v} → action_attrs
событие event — оба словаря в момент времени
вызов invocation — действие точки | цикл | рутина
длительность duration и смещение — сколько длится и когда внутри
цикл cycle — строки <смещение>: вызов
условие [...] и повтор repeat/fill — модификаторы строк
объявления const/fun/pred — значения и вычисления с именами
импорт use — чужие объявления в шапке файла
таблица времени time_const + рутина routine(ТАБЛИЦА) — дни на метках
корневой цикл root_cycle — решётка start_time/duration
расписание schedule — собирает всё в файл
