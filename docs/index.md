# Cyclorithm

**Cyclorithm — DSL для циклических расписаний: процессы описываются циклами так, чтобы их читал человек, а проверял движок. На выходе — плоский список событий.**

```text
cycle CITY_ROUTE duration = 1h20m {
  0m: DEPOT.depart();
  40m: AIRPORT.arrive();
}
```

```console
$ cyclo run route.cyclo --start 2026-01-09T00:00:00 --end 2026-01-10T00:00:00
{"schedule":"Автобусный парк","events":[...18 событий...]}
```

Первый результат за 2 минуты — в [туториале](getting-started/tutorial.md).

## Сравнения

Похожие DSL — таблицей:

| | Cyclorithm | cron | systemd `OnCalendar` | RRULE |
|---|---|---|---|---|
| Единица | Строка с вызовом и данными | Строка-триггер | Выражение-триггер | Правило одного ряда |
| Составное расписание в файле | Да: 8 рейсов двух направлений | Строки без связей | Выражения без связей | События без связей |
| Условия внутри | Предикаты (`weekend`, праздники) | Только поле дня недели | День недели в выражении | Нет, `EXDATE` руками |
| Данные событий | `action_attrs`, `point_attrs` | Нет | Нет | Нет |
| Точность | Секунды и миллисекунды | Минуты | Секунды | Секунды |
| Проверка до запуска | Границы, рекурсия, имена | Нет | Только синтаксис (`systemd-analyze calendar`) | Нет |
| Читает предметник | Да | Частично | Частично | Нет |

Cron уже везде стоит, но синтаксис у него неговорящий: `30 6 * * 1-5`
против `[not weekend(at)] 6h50m`. Для триггеров, которые никто не читает,
сойдёт; для расписаний, которые правит человек, — нет.

RRULE — формат обмена, а не язык описания: его генерируют, руками не пишут.
Мы в него экспортируем — написанное здесь уезжает в любые календарные
клиенты (см. [формат вывода](reference/output.md)).

!!! note "Подсветка кода"
    Отдельного лексера `.cyclo` для Pygments нет — блоки языка
    оформляются как ` ```text `, JSON — как ` ```json `.
