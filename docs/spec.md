# Cyclorithm spec

Каноническое описание языка и поведения `cyclo`. Пример из раздела 1 — контракт: реализация обязана выдавать ровно этот вывод.

## 1. Пример

```text
use "libs/route_lib.cyclo";

fun rush_top(x) = x + 1;

schedule "Автобусный парк" {
  point DEPOT {
    actions = [depart, arrive];
  }

  point AIRPORT {
    actions = [arrive, depart];
  }

  cycle CITY_ROUTE
    duration = 1h20m
  {
    0m: DEPOT.depart();
    40m: AIRPORT.arrive();
    50m: AIRPORT.depart();
    -0m: DEPOT.arrive();
  }

  cycle SHUTTLE
    duration = 20m
  {
    0m: DEPOT.depart();
    20m: DEPOT.arrive();
  }

  root_cycle
    start_time = "2026-01-01T00:00:00",
    duration = 24h
  {
    6h: CITY_ROUTE();
    [hour(at) >= rush_top(MORNING) and not weekend(at)] 10h: repeat 2 SHUTTLE();
    [not weekend(at)] 14h: fill until 15h SHUTTLE();
    [commute(at) and not weekend(at)] 18h: CITY_ROUTE();
    [weekend(at)] 12h: CITY_ROUTE();
  }
}
```

Файл `libs/route_lib.cyclo` рядом (общие объявления, подключаются первой строкой):

```text
const MORNING = 6;

pred commute(at) = morning(at) or evening(at);
```

Что здесь показано: `use`-импорт (`MORNING`, `commute`), свои объявления (`rush_top`), системный файл (`hour`, `weekend`, `morning`, `evening` — `use` не нужен), условия (будние ветки + выходной рейс в 12:00), повторы (`repeat 2`, `fill until 15h` — горизонт от старта `root_cycle`, не от строки) и отрицательное смещение встык (`-0m` ≡ `80m`). Условия со временем суток всегда идут в паре с датой (`weekend`): иначе они константны во всех экземплярах (см. раздел 17).

### Пример поведения программы (CLI)

Входные файлы `route.cyclo` + `libs/route_lib.cyclo` — пример из раздела выше. Окно — пятница 09.01 (будни: работают все ветки; в субботу останутся только рейсы в 6:00 и 12:00).

Вызов:


## 2. Термины

- **schedule** — корневой блок файла. Содержит имя расписания и объявления `point`, `routine`, `cycle`, `root_cycle`. Имя используется в поле `schedule` вывода.
- **point** — именованная точка (место). Объявляет список допустимых `actions` и необязательные атрибуты `attrs` — литерал мапы или ссылку на константу-мапу (`point BELL { actions = [ring]; attrs = CORPUS; }`; без `attrs` — пусто). Каждое событие точки получает копию атрибутов в поле `point_attrs`. Пример: `point DEPOT { actions = [depart, arrive]; }`.
- **action** — именованное действие точки. В выводе — поле `action` события.
- **cycle** — именованный цикл: необязательные параметры `(p1, p2, ...)`, длительность `duration` и список строк `<смещение>: <вызов>;`. Сам по себе ничего не порождает, только вызывается. Пример: `cycle LESSON(subj) duration = 1h35m { ... }`.
- **root_cycle** — корневой цикл: `start_time`, `duration` и список строк `<смещение>: <вызов>;`. Определяет, когда запускаются циклы и одиночные действия.
- **вызов (invocation)** — либо действие точки `<POINT>.<action>()` с необязательным блоком данных `{k = v, ...}`, либо вызов цикла `<CYCLE>(args)` с необязательными аргументами, либо вызов рутины `<ROUTINE>(TABLE, args)` (первый аргумент обязателен и является таблицей). Допустим в любом цикле (`cycle` и `root_cycle`) и в теле рутины; вызовы циклов и рутин могут быть вложенными.
- **блок действий** — `{k = v, ...}` после вызова точки в строке. Значения — выражения уровня условий; событие получает их в поле `action_attrs`.
- **параметр цикла** — имя в заголовке `cycle NAME(p)`: данные строки. Связывается аргументом вызова, виден в условиях и блоках тела (динамический скоуп, см. раздел 4).
- **таблица (`time_const`)** — именованные слоты времени: `time_const DAY duration = 21h35m { 1st: 9h; ... }`. Объявление верхнего уровня (как `const`/`fun`/`pred`), импортируется через `use`. Каждая строка обязана иметь метку; строка с `->` — слот и собственный вызов в одном лице (пожар при каждом инстанцировании с таблицей). Пример: `[workday(at)] lunch: 12h20m -> LUNCH();` — обед только по будням.
- **метка (слот)** — имя смещения в таблице (`1st`, `lunch`; цифры в начале разрешены). В теле рутины стоит вместо смещения и разрешается в смещение таблицы в момент вызова.
- **рутина (`routine`)** — шаблон дня: `routine MONDAY(TC) { 1st: LESSON(...); ... }`. Член `schedule` (после `point`, до `cycle`). Первый параметр — всегда таблица, остальные — данные как у цикла. Вызов `MONDAY(DAY)` инстанцирует тело с таблицей `DAY`: метки заменяются смещениями, пожары таблицы добавляются. Пустая рутина валидна.
- **JSON-значение** — мапа (`Map`, `{"k": v, ...}`), массив (`Array`, `[v, ...]`) или `true`/`false`. Живут в константах, аргументах, блоках и атрибутах точек; в условия напрямую не видны (см. раздел 4).
- **условие** — `[выражение]` перед смещением строки. Вычисляется для абсолютного времени строки (`at`); ложь гасит строку (для цепочек повторов — каждый экземпляр в его старте, см. раздел 17).
- **at** — абсолютное время строки в миллисекундах от unix epoch: запуск объемлющего цикла + смещение (для экземпляра цепочки — его старт). Единственный источник текущего времени в выражениях.
- **объявление** — `const` (значение: число, строка или JSON-данные), `fun` (число от аргумента), `pred` (истина/ложь от `at`); только верхний уровень файла, до `schedule`. Плюс неявный системный файл (календарь и словарь, `use` не нужен).
- **импорт (`use`)** — `use "path";` вверху файла: подключает объявления другого файла (транзитивно). Путь — относительно директории импортирующего.
- **повтор** — модификатор строки между `:` и вызовом: `repeat N` (ровно `N` экземпляров), `fill` (сколько влезет в объемлющий цикл), `fill until T` (сколько влезет до смещения `T` от старта объемлющего цикла). Только для вызовов циклов.
- **event (событие)** — одна запись вывода: `{time, action, point, point_attrs, action_attrs}`. Источник — строка с действием точки внутри вызванного (возможно, вложенного) цикла.
- **смещение / длительность** — человеческий формат: последовательность компонентов `w`, `d`, `h`, `m`, `s`, `ms` (например `0m`, `40m`, `6h`, `1h20m`, `1d2s`).
- **фактическая длительность** — конец занятого циклом отрезка относительно его старта. Считается снизу вверх:
  - вызов действия точки — мгновенный, его длина `0`;
  - вызов цикла `C` — занимает столько, какова объявленная длительность (`duration`) `C`; вызов рутины `M(T)` — длительность таблицы `T`;
  - строка с повтором занимает цепочку экземпляров (см. раздел 4): `repeat N` — `N` стыков, `fill` — столько, сколько влезло в горизонт;
  - строка на смещении `o` заканчивается в `o + длина вызова (цепочки)`;
  - фактическая длительность цикла — самый поздний конец среди его строк; у пустого цикла она `0`.

  Рекурсия запрещена, поэтому фактическая длительность всегда конечна и вычислима статически:

$$
actual(C) = \max_i (o_i + d(X_i))
$$

  где `o_i` — смещение `i`-й строки, `X_i` — то, что она вызывает (`0` для действия точки, объявленная длительность для вызова цикла, длительность таблицы для вызова рутины, длина цепочки для строки с повтором). Для отрицательных смещений `o_i` — эффективное (разрешённое) значение `duration(C) − X`. Выход эффективного смещения за `[0, duration(C)]` (то есть `X` больше длительности объемлющего цикла) — ошибка `E07`. Пример: у `CITY_ROUTE` концы строк `0, 40, 50, 80` → фактическая длительность `80m`, ровно `duration`. А вызов его на `18h` в `root_cycle` заканчивается в `19h20m`, что не превышает `24h` — корректно.

## 3. Грамматика (EBNF)

```ebnf
file        = { use_decl } { decl } schedule ;
use_decl    = "use" string ";" ;
decl        = const_decl | fun_decl | pred_decl | time_const_decl ;
const_decl  = "const" IDENT "=" decl_value ";" ;
fun_decl    = "fun" IDENT "(" IDENT ")" "=" decl_value ";" ;
pred_decl   = "pred" IDENT "(" "at" ")" "=" or_expr ";" ;
time_const_decl = "time_const" IDENT "duration" "=" duration "{" { slot_row } "}" ;
slot_row    = [ "[" condition "]" ] label ":" duration [ "->" invocation ] ";" ;
label       = ( letter | digit | "_" ) { letter | digit | "_" } ;
decl_value  = concat | bitor ;
schedule    = "schedule" string "{" { point } { routine } { cycle } root_cycle "}" ;
point       = "point" IDENT "{" "actions" "=" "[" action_list "]" ";" [ point_attrs ] "}" ;
point_attrs = "attrs" "=" ( map_lit | IDENT ) ";" ;
action_list = IDENT { "," IDENT } ;
cycle       = "cycle" IDENT [ "(" IDENT { "," IDENT } ")" ] "duration" "=" duration "{" { stmt } "}" ;
routine     = "routine" IDENT [ "(" IDENT { "," IDENT } ")" ] "{" { routine_stmt } "}" ;
routine_stmt = [ "[" condition "]" ] routine_offset ":" [ repeat ] invocation ";" ;
routine_offset = [ "-" ] duration | label ;
root_cycle  = "root_cycle" "start_time" "=" string ","
              "duration" "=" duration "{" { stmt } "}" ;
stmt        = [ "[" condition "]" ] [ "-" ] duration ":" [ repeat ] invocation ";" ;
repeat      = "repeat" number | "fill" [ "until" [ "-" ] duration ] ;
condition   = or_expr ;
or_expr     = and_expr { "or" and_expr } ;
and_expr    = not_expr { "and" not_expr } ;
not_expr    = [ "not" ] ( bool_group | comparison | call ) ;
bool_group  = "(" or_expr ")" ;
comparison  = cmp_side ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) cmp_right ;
cmp_side    = bitor | string_expr ;
cmp_right   = bitor | string_expr | "(" bitor { "or" bitor } ")" ;
bitor       = bitxor { "|" bitxor } ;
bitxor      = bitand { "^" bitand } ;
bitand      = shift { "&" shift } ;
shift       = arith { ( "<<" | ">>" ) arith } ;
arith       = term { ( "+" | "-" ) term } ;
term        = factor { ( "*" | "/" | "%" | "floordiv" | "floormod" ) factor } ;
factor      = [ "-" ] ( postfix | "(" bitor ")" ) ;
postfix     = postfix_base { postfix_suffix } ;
postfix_base = number | string | map_lit | array_lit | call | bool_lit | IDENT | truth | "(" bitor ")" ;
postfix_suffix = "." IDENT | "[" [ "-" ] number "]" ;
map_lit     = "{" [ map_pair { "," map_pair } ] "}" ;
map_pair    = map_key ":" literal_value ;
map_key     = '"' { any - '"' } '"' ;
array_lit   = "[" [ literal_value { "," literal_value } ] "]" ;
literal_value = number | string | bool_lit | map_lit | array_lit ;
bool_lit    = "true" | "false" ;
truth       = "(" or_expr ")" ;
string_expr = string_term { "++" string_term } ;
string_term = postfix | "(" string_expr ")" ;
call        = IDENT "(" [ cond_arg { "," cond_arg } ] ")" ;
cond_arg    = bitor | string_expr ;
invocation  = IDENT "." IDENT "(" ")" [ action_block ] | IDENT "(" [ cond_arg { "," cond_arg } ] ")" ;
action_block = "{" [ IDENT "=" cond_arg { "," IDENT "=" cond_arg } ] "}" ;
duration    = duration_item { duration_item } ;
duration_item = number ( "ms" | "w" | "d" | "h" | "m" | "s" ) ;
number      = digit { digit } ;
string      = '"' { any - '"' } '"' ;
IDENT       = ( letter | "_" ) { letter | digit | "_" } ;
letter      = "A" | ... | "Z" | "a" | ... | "z" ;
digit       = "0" | ... | "9" ;
any         = ? любой символ, кроме '"' и переноса строки ? ;
```

Примечания:
- Лексика: пробелы, табы и переносы строк между токенами игнорируются. Строчные комментарии `//` до конца строки выбрасываются лексером как пробелы (разрешены между любыми токенами, внутри строк `"..."` — обычный текст). Блочных комментариев нет. Пример: `6h: CITY_ROUTE();  // утренний запуск`.
- Имена (`IDENT`): ASCII-буквы, цифры и `_`; начинаются с буквы или `_`; регистр значим (`DEPOT` ≠ `Depot`). Кириллица и другие не-ASCII в именах запрещены.
- Строки: однострочные, без экранирования; кавычка `"` внутри строки не представима.
- Порядок объявлений: сначала `const`/`fun`/`pred`/`time_const`, затем `point`, затем `routine`, затем `cycle`, затем `root_cycle`. `root_cycle` — ровно один.
- Имена точек, рутин и циклов живут в общем пространстве: одно имя не может обозначать два рода (нарушение — `E09`: `point 'X' is not a routine`, `routine 'X' is not a cycle`, `point 'X' is not a cycle`). Таблицы — в своём пространстве (с выражениями не пересекаются). Имена действий — в пространстве своей точки: одно и то же имя в разных точках допустимо (как `depart` в примере). Повторы имени внутри одной точки (`actions = [x, x]`) разрешены — проверка `E02` идёт по вхождению, дубликаты ни на что не влияют.
- Различение вызовов по форме: `A.b()` — действие точки `A`, `A()` — вызов цикла или рутины `A` (рутина — если имя объявлено рутиной; первый аргумент тогда таблица). Имя не может одновременно обозначать точку и цикл/рутину (`routine 'X' is not a point`).
- Параметры рутины (`routine MONDAY(TC, subj)`): первый — таблица, остальные — данные. Пустые параметры (`routine M { ... }`) — `E12` (`routine 'M' has no table parameter`); дубли имён — `E04`; вызов с неверным числом аргументов — `E12`. Первый аргумент вызова обязан быть именем таблицы (проброс своего табличного параметра или литерал из реестра): неизвестная таблица — `E16` (`unknown table 'SHORT'`), не имя — `E16` (`invalid table argument for 'M'`).
- Метки слотов (`1st`, `lunch`): буквы, цифры и `_`, цифра в начале разрешена. В строке рутины сначала пробуется длительность, потом метка (иначе `45m` читалось бы меткой); граница слова после длительности обязательна (иначе `1st` резалось бы на `1s` + мусор). Ловушка: имя вида `1ms` разберётся длительностью, а не меткой, — таких имён не давать. Минус — только у длительности (`-10m` от конца таблицы; `-1st` — синтаксис).
- Строки таблицы (`label: смещение [-> вызов];`): смещение — неотрицательная длительность от старта таблицы; пожар `->` — любой вызов (действие точки, цикл, рутина с явной таблицей) с опциональным условием. Дубли меток — `E04` (`duplicate slot '1st'`).
- Блоки действий (`A.x() { k = v, ... }`): только у вызовов точек — у цикла после `)` блока нет (иначе синтаксис). Ключи — `IDENT`, значения — выражения уровня условий; дубли ключей — `E15`.
- Литералы данных: содержимое мап и массивов — только литералы (числа, строки, `true`/`false`, вложенные мапы/массивы; без вычислений и имён). Дубли ключей мапы — `E15` (валидация). Висячих запятых нет (строго, как везде).
- Доступ: `.поле` — только имя, цепочки — слева направо (`subj.meta.n`); `[n]` — только целочисленный литерал (минус слитно, как у смещений: `m[-1]` ок, `m[- 1]` — синтаксис; границы — `E12` в момент строки). `BELL.ring()` остаётся вызовом: различие по скобке. Вычисляемых ключей (`m[expr]`) нет.
- `true`/`false` — литералы (с границей слова: `truex` — имя, `true(x)` — по-прежнему вызов).
- Длительности — только человеческий формат: компоненты `w` (недели), `d` (сутки), `h` (часы), `m` (минуты), `s` (секунды), `ms` (миллисекунды). Примеры: `80m`, `24h`, `1h20m`, `1d2s`. Каждый компонент — не более одного раза, порядок строго по убыванию (`w > d > h > m > s > ms`). `ms` токенизируется как единый юнит, а не `m` + `s`. Порядок и уникальность компонентов — проверка валидации (`E05`), грамматика их пропускает. Значение обязано влезать в `i64` миллисекунд (лимит — около 292 млн лет, то есть около 1.07*10^11 суток), иначе `E05`.
- Пустой `actions = []` запрещён грамматикой — осознанно: точка без действий бессмысленна.
- Минус у смещения строки (`-10m: ...`): разрешён только здесь, пишется слитно с длительностью (`-10m` ок, `- 10m` — синтаксическая ошибка). В заголовках (`duration = …`) длительности остаются неотрицательными. Минус относится ко всей длительности (`-1h20m` = минус 80 минут, не покомпонентно).
- Повторы (`repeat N`, `fill`, `fill until T`): модификатор строки между `:` и вызовом. `repeat`, `fill`, `until` распознаются по позиции; точкам, циклам и действиям такие имена не давайте (цикл с таким именем фактически невызываем в этих позициях). Число в `repeat N` — десятичное (`number`); `repeat 0` запрещён. Минус в `until` — слитно, как у смещений строк. Комбинации `repeat N until T` нет: `until` — только с `fill`. Повторы действий точки запрещены (только циклы).
- Условия (`[...]`): выражение в скобках перед смещением. Операнд с голым вызовом (`[weekend(at)]`) — предикат, остальные позиции требуют сравнения. Приоритеты: `(…)` (атом сильнее всего) → унарный минус → `*` `/` `%` `floordiv` `floormod` → `+` `-` → `++` → `<<` `>>` → `&` → `^` → `|` → сравнение → `not` → `and` → `or`, слева направо. `++` — строковая альтернатива (пробуется раньше числового выражения); битовые — только числа. Сравнения не цепочатся (`a < b < c` — синтаксическая ошибка). Скобки `(…)` — атомы на обоих уровнях: в позиции условия группа держит полное `or`/`and` и переопределяет приоритет (`(a == 1 or b == 2) and c == 3`), в арифметической — мостик `truth` (`12 * (mp >= 10 and x == 1)` даёт `1`/`0`); группа прозрачна, узла в AST нет. `and` внутри числовой альтернации `(a or b)` — синтаксическая ошибка (ветки альтернации — `bitor`, булево `or` пишется группой). Строковые ветки — только под строку слева (`datestr(at) == ("2026-11-04" or "2026-12-31")`); смешение строк с числами в ветках — `E12`. Голое число или арифметика без сравнения (`[5]`, `[at + 1]`) — синтаксическая ошибка. Из имён видны объявления файла (`const`/`fun`/`pred`, см. ниже) и системный файл; `at` — значение времени строки; остальное — ошибка `E11`. Ключевые слова `or`, `and`, `not`, `floordiv`, `floormod` распознаются по позиции.
- Самовызов (прямой или через цепочку) запрещён для циклов, рутин и таблиц: общий граф вызовов (пожары `->` — рёбра таблицы), сообщения — `recursive cycle/routine/table` (всё `E06`).

## 4. Семантика

1. `root_cycle` задаёт бесконечную периодическую решётку: якорь `start_time`, период `duration` (подробности — в подразделе «Время и арифметика»).
2. Каждая строка `<смещение>: <вызов>;` выполняется в момент `(запуск объемлющего цикла + смещение)`. Отрицательное смещение `-X` в теле цикла `C` (включая `root_cycle`) разрешается статически как `duration(C) − X`, где `duration(C)` — объявленная длительность непосредственно объемлющего цикла; дальше строка живёт как обычно (участвует в фактической длительности, проверке `E07`, сортировке). Пример: в `cycle CITY_ROUTE duration = 1h20m` строка `-10m: DEPOT.arrive();` эквивалентна `70m`, а `-0m` — ровно концу (`80m`, встык валидно).
3. Вызов цикла `<CYCLE>()` — запуск цикла в этот момент; его строки разворачиваются рекурсивно с накоплением смещений. Вложенность не ограничена, кроме запрета рекурсии. Вызов с аргументами `<CYCLE>(v, ...)` связывает параметры цикла (см. правило 19); число аргументов обязано совпадать с числом параметров, иначе `E12`. Вызов рутины `<ROUTINE>(TABLE, v, ...)` — то же с таблицей первым аргументом (см. правило 22); число аргументов обязано совпадать с числом параметров, иначе `E12`.
4. Вызов действия `<POINT>.<action>()` — событие в этот момент. Допустим и внутри `cycle`, и напрямую в `root_cycle` (одиночное событие). Блок после вызова (`A.x() { k = v, ... }`) вычисляется в момент строки и попадает в событие полем `action_attrs` (см. правило 20).
5. События попадают в вывод, если их `time` входит в интервал CLI `[start, end)`. События вне интервала отбрасываются. `end <= start` — не ошибка: пустой `events`, код возврата 0.
6. События в выводе упорядочены по `(time, k, порядок объявления)`, где `k` — номер экземпляра `root_cycle`. Дубликаты (совпавшие `time`, `action`, `point`) сохраняются, схлопывания нет.
7. Проверка при разворачивании: точка должна быть объявлена, действие должно входить в её `actions`, цикл должен быть объявлен, рекурсивных цепочек вызовов быть не должно. Иначе — ошибка (см. раздел 5).
8. Граница цикла: фактическая длительность каждого цикла (`cycle` и `root_cycle`, без исключений) обязана умещаться в его объявленную длительность: `actual(C) ≤ duration(C)`. Иначе — ошибка `E07`. Граница включительная: завершение ровно встык валидно. В сообщении указывается вызов со строки, давшей максимум (при равных концах — первая в порядке объявления). Пример: цикл 1 (`duration = 1h`) вызывает на `40m` цикл 2 (`duration = 40m`) → конец на `40m + 40m = 80m > 60m`, вылезает на `20m` → ошибка. Следствие для `root_cycle`: цепочки, перетекающие через границу периода (например, смена `22:00 → 06:00` при `duration = 24h`), запрещены — для них выбирается больший `duration` (например, `48h`) или сдвинутый `start_time`.
9. Повторы строк (`repeat N`, `fill`, `fill until T`): строка выполняется не один раз, а цепочкой экземпляров. Экземпляры стыкуются последовательно: старт следующего = конец предыдущего (по объявленной длительности вызываемого цикла). Повторы допустимы только для вызовов циклов (действие точки с повтором — ошибка `E10`).
10. `repeat N X()` — **строгий режим**: ровно `N` экземпляров (`N ≥ 1`, иначе `E10`); вся цепочка обязана влезть в объемлющий цикл, иначе обычный `E07` на строке (конец цепочки вместо конца одиночного вызова).
11. `fill X()` / `fill until T X()` — **мягкий режим**: экземпляры добавляются, пока `старт + duration ≤ горизонт`, где горизонт — конец объемлющего цикла для `fill` и смещение `T` от старта объемлющего цикла для `fill until T`. Первый невлезший экземпляр пропускается (и все дальнейшие тоже), это не ошибка; влезло ноль — ноль событий. Граница включительная. Отрицательный `until -X` разрешается как `duration(родителя) − X`, как отрицательные смещения. Горизонт обязан лежать в `[0, duration(родителя)]`, иначе `E07`. Эквивалентности: `fill X()` ≡ `fill until <конец родителя> X()`; `fill until -0m X()` ≡ `fill X()`.
12. Условие строки вычисляется для абсолютного времени строки (`at`): запуск объемлющего цикла + смещение, включая цепочки повторов и вложенные вызовы. Ложь = пропуск строки целиком (действие или вложенный цикл не выполняются, событий нет); пропуск родителя гасит потомков. Условия не наследуются. Статическая фактическая длительность и `E07` считаются как будто все условия истинны. Сортировка без изменений.
13. Выражения условий: целочисленная арифметика (`+`, `-`, `*`, `/` усекающее к нулю, `%` со знаком делимого, `floordiv`/`floormod` к минус бесконечности, унарный минус); сравнения чисел и строк (строки — побайтово, все 6 операторов); логика `not`/`and`/`or`; `++` — конкатенация строк; `str(n)` — десятичная запись числа; `pad(n, w)` — та же запись, дополненная слева нулями до ширины `w`. Арифметика — только над числами, `++` — только над строками, сравнения — число с числом или строка со строкой, иначе `E12` (исключение — голый `at` рядом со строкой: см. §4.13). У `str` — ровно 1 числовой аргумент, у `pad` — ровно 2 числовых, иначе `E12`. `mkdate(y, mo, d, h, mi, s, ms)` — конструктор даты из 7 чисел (наивное время, как везде): месяц `1..12`, день в пределах месяца (февраль високосный), `h 0..23`, `mi`/`s 0..59`, `ms 0..999`; годы — весь `i64` (пролептический григорианский). Возвращает миллисекунды epoch — обычное число для сравнений и арифметики. Кривые компоненты — `E12` (`invalid date 'Y-M-DTh:m:s.ms'`, числа как даны); переполнение сборки в миллисекунды — `E12` (`integer out of range`). `floordiv(a, b)`/`floormod(a, b)` — те же операции в виде функций (так пишет системный файл). Битовые операторы `<<`, `>>`, `&`, `|`, `^` — только над числами, иначе `E12`: two's complement с wrap'ом (уехавшие биты роняются, `E12` не бывает), `>>` — логический (сдвиг беззнакового представления, добивка нулями), величина сдвига — по модулю 64 через евклидов остаток (`1 << 64` ≡ `1`, `1 << -1` ≡ `1 << 63`). Деление и остаток на ноль — `E12`: константный ноль ловится статически, ноль выражения — в момент строки (тоже ошибка, не пропуск). Даты как строки: голый `at` в сравнении со строкой приводится к канонической форме `datetimestr(at)` (`YYYY-MM-DDTHH:MM:SS.mmm`); строковые литералы нормализуются (`"2026-06-01"` — полночь, `"2026-06-01T05:00"` — нулевые секунды, полная форма как есть), кривой литерал и год вне `0000…9999` — `E12`. Любое другое смешение числа и строки — `E12`; арифметики дат нет, только сравнения.
14. Объявления (`const`/`fun`/`pred`, только верхний уровень файла, до `schedule`): `const NAME = ...` — любое значение (число, строка, мапа, массив, `true`/`false`), `fun NAME(x) = ...` — число от аргумента, `pred NAME(at) = ...` — истина/ложь (параметр предиката пишется буквально `at`). Тела подставляются в места использования; рекурсия (прямая и через цепочку) — ошибка `E12`. Все имена — в одном пространстве; дубли внутри файла — ошибка `E04`.
15. Системный файл незаметно подставляется перед каждой программой (`use` писать не нужно): календарь и словарь (`mon`…`sun`, `weekend`, `workday`, `day_of_week` (`Mon=1 … Sun=7`, рядом с `dow` `0=mon … 6=sun`), времена суток, сезоны, `hour`/`day`/`month`/`year`/`quarter`, `is_leap`, `days_in_month`, `start_of_day`/`start_of_month`, `datestr`/`datetimestr`), детерминированный ГСЧ `rand(t)` — xorshift32 от младших 32 бит миллисекунд, выход `0..9999` (пример: `[rand(at) < 5000]` — честная монетка). Один и тот же вход даёт один и тот же выход в любом прогоне — чистая функция, состояния и сидов нет. Переопределение системного имени в программе — разрешено молча, побеждает последнее (порядок: системный файл, затем тело программы). Имена на `__` видны только в своём файле: обращение к чужому `__`-имени — ошибка `E11`.
16. Импорты (`use "path";`, только вверху файла, до объявлений): путь — относительно директории импортирующего файла; импортированный файл — только объявления (может содержать свои `use`, но не `schedule`). Оверлей общий: системный файл → импорты в порядке обхода вглубь → тело программы; одно имя в разных файлах — молча побеждает последнее, дубли внутри одного файла — `E04`. `__`-имена границу файла не пересекают. Ненайденный файл и цикл импорта — `E13`; `schedule` внутри импорта — `E14`.

### Время и арифметика

Внутреннее представление времени — `i64`, миллисекунды от unix epoch (`1970-01-01T00:00:00Z`).

Входные строки без таймзоны (тот же формат, миллисекунды опциональны) трактуются как наивное время 1:1, без сдвигов. Таймзоны и DST не учитываются, сутки всегда равны 24h.

Длительности фиксированные: `w = 7d`, `d = 24h`, далее в миллисекундах. Високосные секунды игнорируются.

Решётка `root_cycle`: экземпляры с периодом `P = duration` от якоря `T0 = start_time`:

$$
T(k) = T_0 + k \cdot P, \quad k = 0, 1, 2, \dots
$$

Активный экземпляр для момента `t >= T0`:

$$
k(t) = \left\lfloor \frac{t - T_0}{P} \right\rfloor, \quad S(t) = T_0 + k(t) \cdot P
$$

При `t < T0` экземпляров нет. Вся арифметика целочисленная (миллисекунды).

Строятся только экземпляры, чьи события могут попасть в окно запроса. Пусть `S` — фактическая длительность `root_cycle` (статически известна, `S ≤ P` по правилу 8; это горизонт занятости — все события экземпляра лежат внутри него). Тогда первый кандидат:

$$
k_{min} = \max\left(0, \left\lceil \frac{start - S - T_0}{P} \right\rceil\right)
$$

строить, пока `T(k) < end`.

Более ранние экземпляры заканчиваются до `start`, более поздние начинаются после `end`. Пример из раздела 1: `P = 24h`, `S = 19h20m`, окно `10.01–11.01` → строится ровно один экземпляр (`k = 9`, старт `10.01 00:00`).

Фильтр применяется ко времени события (`T(k)` + цепочка смещений входит в `[start, end)`), а не к старту экземпляра. Правило 8 гарантирует, что события экземпляра лежат внутри `[T(k), T(k) + P]`.

Обратно в вывод: миллисекунды преобразуются в наивную ISO-строку (см. раздел 6).

17. Выражения условий: типы, вызовы, порядок проверок. Значений пять: число (`Num`, `i64`; `at` — миллисекунды от epoch), строка (`Str`), `true`/`false`, мапа (`Map`, упорядоченный словарь) и массив (`Array`). Типа «булево» в условиях нет: условие — это `or`/`and`/`not`, сравнение или голый вызов предиката; внутрь арифметики истину вносит только мостик `truth` (`1`/`0`), принимающий полное условие, а не одно сравнение. Данные (мапы, массивы, `true`/`false`) напрямую в условиях невидимы: голое имя константы-данных и доступ через него (`M`, `M.n`) — ошибка `E11`; путь данным — только параметры циклов (см. правило 19). Проверок две: статическая (все условия файла, порядок — раздел 5) и вычисление в момент строки. Статически ловятся: смешение типов, арность, деление на константный ноль, кривой все-константный `mkdate`, невлезающий литерал числа, кривой литерал даты, рекурсия, дубли ключей (`E15`), `E11`. В момент строки: деление на ноль выражением, кривой `mkdate` выражением, переполнение (см. ниже), оператор кроме `==`/`!=` с альтернацией, ошибки доступа к данным (`unknown field`, `index out of bounds`). `at` — старт экземпляра строки; для цепочек `repeat`/`fill` проверяется каждый экземпляр в его старте: ложь гасит только этот экземпляр (дыры, не сдвиг сетки). В телах объявлений `at` — время места вызова. Арифметика и битовые — только над числами (иначе `E12`); переполнение любой арифметической операции и унарного минуса — `E12` (текст черновой: `integer out of range '...'`, решение отдельно), битовые переполняться не могут по определению (wrap). Сравнения — число с числом, строка со строкой; мапа/массив с мапой/массивом — `E12` (`cannot compare maps or arrays`, глубокое сравнение — будущее решение, см. правило 18); участие `true`/`false` — `E12` (смешение); исключение — буквально голый `at` рядом со строковым литералом (`at + 0` уже не приводится; длины литерала 10/16/19/23, иначе `invalid date`). `at` — старт экземпляра строки; для цепочек `repeat`/`fill` проверяется каждый экземпляр в его старте: ложь гасит только этот экземпляр (дыры, не сдвиг сетки). В телах объявлений `at` — время места вызова. Альтернация `(a or b)` — только числа (по грамматике) и только с `==`/`!=`: `==` — равен любому, `!=` — не равен всем; другой оператор проходит статику, но даёт `E12` в момент строки. `++` — только строки. `str(n)` — 1 числовой аргумент; `pad(n, w)` — 2 числовых (`w < 0` — без дополнения, число длиннее ширины — как есть). `const` вызывается без аргументов, `fun` — ровно с 1, `pred` — ровно с 1 числовым (любое числовое выражение, станет `at` тела), `mkdate` — ровно с 7 числовыми; `pred` в позиции значения и не-предикат в позиции предиката — `E12`; голые `fun`/`pred` без вызова — `E12`; неверное число аргументов — `E12`. Встроенные `str`/`pad`/`floordiv`/`floormod`/`mkdate` переопределяемы на общих основаниях. Видимость имён — разделы 15–16 (неизвестное и чужое `__` — `E11`, любая рекурсия — `E12`). `or`/`and` ленивы слева направо: ошибка вычисления в невычисленной ветке не срабатывает (деление на ноль в мёртвой ветке — не ошибка), но статическая проверка идёт по всем ветвям.

18. Данные: мапы, массивы, `true`/`false`. Литералы — в питоновском духе (`{"name": "БЖД", "tags": ["утро"]}`); содержимое — только литералы (чистые данные, без вычислений и имён). Порядок ключей мапы — порядок объявления; дубли ключей — ошибка `E15`. Доступ — точкой (цепочки: `subj.meta.n`) и индексом (`tags[0]`, неотрицательный целочисловой литерал, отсчёт от 0); вычисляемых ключей нет. Ошибки доступа — только в момент строки, все `E12`: `unknown field 'name'` (нет ключа, поле не-мапы, индекс не-массива), `index out of bounds '5'` (выход за границы, отрицательный индекс). Сравнение мап/массивов (`==`/`!=`, даже между собой) — `E12` `cannot compare maps or arrays`: глубокое сравнение — будущее решение, молча не реализовывать. `true`/`false` хранятся и едут в JSON как есть; в условиях им не место (`E12`, см. правило 17).

19. Параметры циклов: `cycle LESSON(subj) duration = 1h35m { ... }`, вызов `LESSON(BJD_LECTURE)` — аргументы вычисляются в момент строки в окружении вызывающего (произвольные выражения: константа-мапа, инлайн-литерал, в теории число). Параметр виден в теле цикла — в условиях (`[subj.type == "лек"]`) и в блоках. Скоуп динамический: окружение течёт вниз по цепочке вызовов (строки безаргументного `INNER`, вызванного из `LESSON`, видят `subj`); вложенный вызов со своим аргументом перетирает параметр целиком. Параметр затеняет `const`/`fun`/`pred` с тем же именем в теле цикла. Имя константы-данных напрямую в условии (`[BJD_LECTURE.type == ...]`) запрещено — `E11` (в скоупе условий только параметры и числа/строки). Несвязанный в момент строки параметр — тоже `E11` (статика пропускает: имя — параметр какого-то цикла). Самовызов с параметрами — всё равно рекурсия (`E06`); дубли параметров (`cycle C(a, a)`) — `E04`. Данные рутины (`params[1..]`) — те же правила; табличный параметр (`params[0]`) в условиях и блоках невидим — `E11` (при развёртке затирается из окружения; совпадение именем с параметром цикла не спасает).

20. Словари события. Блок действий (`0m: BELL.ring() { subject = subj.name, event = "start" };`): ключи — `IDENT`, значения — выражения уровня условий (литералы, `subj.поле`, `at`-арифметика, вызовы `fun`); предикат в позиции значения — `E12`; дубли ключей — `E15`; пустой блок `{}` разрешён; порядок ключей в JSON — порядок блока. Вычисленный словарь попадает в событие полем `action_attrs`. Атрибуты точки (`attrs = CORPUS;` — литерал или ссылка на константу-мапу; без поля — пусто) разрешаются в начале развёртки (после всех проверок раздела 5): неизвестное имя — `E11`, не мапа — `E12`; дубли в литерале — `E15`. Каждое событие (включая экземпляры `repeat`/`fill`) получает свою копию словаря точки полем `point_attrs`. Оба поля присутствуют в событии всегда; нет данных — пустой `{}`.

21. Таблицы (`time_const`, только верхний уровень, до `schedule`; импортируются через `use`, между файлами побеждает последнее, дубли внутри файла — `E04` `duplicate table 'T'`). Длительность обязана быть корректной (`E05`) и покрывать концы всех строк, включая пожары (`E07` с виной на таблице: `action 'x' overruns 'DAY' by ...`). Пожар без повторов выполняется в смещении слота при каждом инстанцировании с таблицей — со своим условием (условия и вызовы пожаров проверяются без параметров: только глобальные имена и `at`). Вызов рутины в пожаре — с явной таблицей. Имя таблицы в выражениях невидимо (`E11`).

22. Рутины (`routine`, член `schedule` после `point`, до `cycle`). Вызов `MONDAY(DAY)` инстанцирует тело: метки заменяются смещениями таблицы (нет метки — `E16` `unknown slot '8th'`), проброс табличного параметра (`MONDAY(TC)` внутри `WRAP(TC)`) — литеральным именем, пожары таблицы добавляются после строк тела. Длительность вызова — длительность таблицы (шаг цепочек `repeat`/`fill`, граница `E07` в месте вызова). Тело проверяется в длительности таблицы для каждой пары `(рутина, таблица)` первого использования (порядок — циклы, рутины, корень, пожары; вина `E07`/`E10` — на рутине: `cycle 'C' overruns 'M' by ...`); невызываемая рутина — только статика имён и условий (покрытие без таблицы проверить нечем). Спан события именуется рутиной; пожар, вызывающий цикл, даёт вложенный спан цикла. Таблица обязана покрывать все метки тела (строгость: сокращённый день без `7th`, а рутина её использует, — ошибка, а не молчаливый пропуск).

## 5. Ошибки

Формат: текст ошибки в stderr, в stdout ничего. Коды возврата: `0` — успех; `1` — ошибка ввода, парсинга или валидации; `2` — неверные аргументы CLI (текст usage, см. ниже).

Ошибки синтаксиса (файл не разбирается по грамматике из раздела 3 — включая отсутствие `root_cycle`) → код `1` + текст в stderr, без E-кода. Коды `E01–E16` — только валидация уже разобранного AST. Импорты (`E13`, `E14`) разрешаются раньше всех проверок решётки: файл не найден и цикл — до разбора импортированного, `schedule` внутри — сразу после разбора. Отсутствие обязательных аргументов `--start`/`--end` → код `2` + usage в stderr:

```text
usage: cyclo run FILE --start DATETIME --end DATETIME
```

Невозможно прочитать файл → код `1` + `cannot read 'FILE': ...` в stderr.

Проверки валидации идут фазами в фиксированном порядке, первая ошибка побеждает; внутри фазы — в порядке объявления: имена (`E04` — дубли точек, рутин, циклов, параметров, таблиц и слотов, столкновение имён `E09`, затем вызовы `E01`/`E02`/`E03`/`E09`, арность циклов и рутин `E12`, форма таблицы вызова `E16`) → рекурсия (`E06`: циклы, рутины, таблицы) → таблицы (`E16` — покрытие меток, `E05`/`E07`/`E10` — длительности и границы таблиц и тел) → длительности, повторы и границы (`E05`, `E10`, `E07`) → условия и тела определений (`E11`, `E12`, `E15`: сначала объявления в порядке объявления, затем строки циклов, рутин и корня, затем пожары таблиц) → даты (`E08`: сначала `--start`/`--end`, затем `start_time`). Деление на ноль выражением ловится в момент строки при разворачивании — тоже `E12`; дубли ключей в `attrs` точек и ошибки доступа к данным — в начале развёртки (после всех проверок выше).

| Код | Случай | Пример сообщения |
|-----|--------|------------------|
| E01 | Неизвестная точка | `unknown point 'PORT'` |
| E02 | Действие не разрешено для точки | `action 'arrive' not allowed for point 'DEPOT'` |
| E03 | Неизвестный цикл | `unknown cycle 'NIGHT_ROUTE'` |
| E04 | Дублирующее объявление | `duplicate point 'DEPOT'`, `duplicate routine 'M'`, `duplicate table 'T'`, `duplicate slot '1st'`, `duplicate param 'a'` (параметры циклов и рутин) |
| E05 | Некорректная длительность | `invalid duration '1x'`, `invalid duration '1h2h'`, `invalid duration '30s1d'`, `invalid duration '106751991168d'` (переполнение: первые сутки сверх лимита `i64`, `106751991167d` ещё влезает), нулевой период `root_cycle` |
| E06 | Рекурсивный вызов | `recursive cycle 'A'`, `recursive routine 'M'` (цикл через рутину и обратно), `recursive table 'T'` (пожар, инстанцирующий рутину с той же таблицей) |
| E07 | Вызов выходит за границу объемлющего цикла | `cycle 'CYCLE2' overruns 'CYCLE1' by 20m (80m > 60m)`; для действия точки симметрично: `action 'x' overruns 'R' by 1m (61m > 60m)`; отрицательное смещение ниже нуля: `offset '-2h' out of bounds (duration 1h20m)`; цепочка `repeat N` за границей — конец цепочки вместо конца одиночного вызова; горизонт `until` вне `[0, duration]`: `until '30h' out of bounds (duration 24h)` |
| E08 | Некорректная дата/время | `invalid datetime '...'` (битый `start_time` или `--start`/`--end`) |
| E09 | Перепутан род имени | `point 'DEPOT' is not a cycle`, `cycle 'X' is not a point`, `point 'X' is not a routine`, `routine 'X' is not a point`, `routine 'X' is not a cycle` |
| E10 | Некорректный повтор | `invalid repeat count '0'` (`repeat 0`, сюда же невлезающее в `u64` число); `fill of zero-duration cycle 'LONG'` (`fill`/`fill until` по циклу нулевой длительности — бесконечность); `repeat of point action 'depart' not allowed` (повторы только для циклов) |
| E11 | Неизвестное имя в условии | `unknown name 'banana'` (включая обращение к чужому `__`-имени, имя константы-данных напрямую в условии, несвязанный параметр в момент строки, табличный параметр рутины, имя таблицы) |
| E12 | Некорректное выражение условия | `type mismatch: cannot mix number and string`; `wrong arguments for 'pad'` / `wrong arguments for 'mkdate'` / `wrong arguments for 'LESSON'` (арность циклов и рутин); `routine 'M' has no table parameter` (у рутины нет табличного параметра); `division by zero`; `recursive definition 'a'`; `'hour' is not a predicate` (вызов не-предиката в позиции условия); `invalid date '...'` (кривая дата: литерал или `mkdate`); `integer out of range '...'` (невлезающий литерал числа; переполнение арифметики и сборки `mkdate` — черновик, см. §4.17); `unknown field 'name'` (нет ключа, поле не-мапы, индекс не-массива); `index out of bounds '5'`; `cannot compare maps or arrays` |
| E13 | Ненайденный импорт или цикл | `cannot read import '...'`, `import cycle '...'` |
| E14 | Расписание в импорте | `schedule not allowed in import '...'` |
| E15 | Дублирующий ключ атрибутов | `duplicate attribute 'a'` (литерал мапы, блок действий) |
| E16 | Неизвестная таблица или слот | `unknown table 'SHORT'` (таблицы с таким именем нет); `unknown slot '8th'` (метки нет в таблице вызова); `invalid table argument for 'M'` (первый аргумент рутины — не имя таблицы) |

## 6. Формат вывода

Одно событие:

```json
{"time": "2026-01-10T06:00:00", "action": "depart", "point": "DEPOT", "point_attrs": {}, "action_attrs": {}}
```

- `time` (string, обязательно) — наивный ISO8601 `YYYY-MM-DDTHH:MM:SS`, при наличии миллисекунд — `.mmm`.
- `action` (string, обязательно) — имя действия из `actions` точки.
- `point` (string, обязательно) — имя точки (`IDENT` из исходника).
- `point_attrs` (object, обязательно) — копия атрибутов точки (`attrs`, см. правило 20); нет атрибутов — пустой `{}`.
- `action_attrs` (object, обязательно) — вычисленный блок строки (см. правило 20); нет блока — пустой `{}`.

Корневой объект:

```json
{
  "schedule": "Автобусный парк",
  "start": "2026-01-10T00:00:00",
  "end": "2026-01-11T00:00:00",
  "events": []
}
```

- `schedule` (string) — имя из `schedule "..."`.
- `start` / `end` (string) — интервал из аргументов CLI, эхо.
- `events` (array) — события по разделу 4, упорядочены по `(time, k, порядок объявления)`.

JSON Schema (draft 2020-12):

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["schedule", "start", "end", "events"],
  "additionalProperties": false,
  "properties": {
    "schedule": {"type": "string"},
    "start": {"type": "string"},
    "end": {"type": "string"},
    "events": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["time", "action", "point", "point_attrs", "action_attrs"],
        "additionalProperties": false,
        "properties": {
          "time": {"type": "string"},
          "action": {"type": "string"},
          "point": {"type": "string"},
          "point_attrs": {"type": "object"},
          "action_attrs": {"type": "object"}
        }
      }
    }
  }
}
```
