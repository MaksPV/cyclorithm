# Формат вывода

## Событие

```json
{"time": "2026-01-10T06:00:00", "action": "depart", "point": "DEPOT", "point_attrs": {}, "action_attrs": {}}
```

- `time` — время события в формате ISO 8601
  (`YYYY-MM-DDTHH:MM:SS[.mmm][Z|±HH:MM]`). Смещение в выводе задаёт
  `start` для `run` или `from` для `next`. Если у этого аргумента нет
  смещения, используется `timezone` программы. Если смещение нигде
  не задано, время выводится без суффикса.

  | `timezone` программы | Начало окна без смещения | Начало окна с `Z` | Начало окна с `±HH:MM` |
  |---|---|---|---|
  | Не указана | Без суффикса | `Z` | Смещение начала окна |
  | `Z` | `Z` | `Z` | Смещение начала окна |
  | `±HH:MM` | Смещение программы | `Z` | Смещение начала окна |

  Относительное начало окна (например, `--start +1d`) использует текущее
  смещение системной зоны. Смещение аргумента `end` влияет только на
  момент окончания окна. Как зона влияет на расчёт событий, описано
  в [семантике](semantics.md#time-zones).
- `action` — имя из `actions` точки. `point` — имя точки (`IDENT` исходника).
- `point_attrs` — копия атрибутов точки `attrs`; при отсутствии — пустой `{}`.
- `action_attrs` — вычисленные атрибуты действия строки; при отсутствии — `{}`.
- Порядок событий: `(time, k, порядок объявления)`, где `k` — номер экземпляра
  корневого цикла. Совпавшие события остаются отдельными записями.

## Объект команды run

```json
{"schedule": "Автобусный парк", "start": "...", "end": "...", "events": []}
```

Поля `start`/`end` повторяют аргументы CLI. Машиночитаемая схема —
[output.schema.json](../schemas/output.schema.json) (draft 2020-12):
все `.expected.json` примеров ей соответствуют.

## Объект команды next

Объект содержит `schedule`, `from`, `within` и `events`. В поле `from`
записано вычисленное начало окна в формате ISO 8601, а `within` содержит
длительность окна в миллисекундах. В режиме `--ndjson` обе команды
выводят только события, по одному JSON-объекту на строку.
