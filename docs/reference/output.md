# Формат вывода

## Событие

```json
{"time": "2026-01-10T06:00:00", "action": "depart", "point": "DEPOT", "point_attrs": {}, "action_attrs": {}}
```

- `time` — наивная строка ISO8601 `YYYY-MM-DDTHH:MM:SS`; при наличии
  миллисекунд — с суффиксом `.mmm`.
- `action` — имя из `actions` точки. `point` — имя точки (`IDENT` исходника).
- `point_attrs` — копия атрибутов точки `attrs`; при отсутствии — пустой `{}`.
- `action_attrs` — вычисленные атрибуты действия строки; при отсутствии — `{}`.
- Порядок событий: `(time, k, порядок объявления)`, где `k` — номер экземпляра
  корневого цикла. Совпавшие события сохраняются, схлопывания нет.

## Объект команды run

```json
{"schedule": "Автобусный парк", "start": "...", "end": "...", "events": []}
```

Поля `start`/`end` повторяют аргументы CLI. JSON Schema (draft 2020-12) —
в [полной спеке](../spec.md).

## Объект команды next

Объект `schedule,from,within,events`: `from` — разрешённая ISO-строка,
`within` — миллисекунды числом. Флаг `--ndjson` выводит по событию на строку.

## Календарь ICS

Флаг `--format ics` возвращает календарь RFC 5545 вместо JSON: заголовок
`VCALENDAR`, каждое событие — `VEVENT` без `DTEND` (события мгновенны).
Соответствие полей: `UID` — детерминированный (хеш расписания, времени,
действия, точки и порядкового номера); `DTSTAMP` — момент формирования;
`DTSTART` — время события с суффиксом `Z` (наивное время трактуется как UTC);
`SUMMARY` — `action @ point`; `DESCRIPTION` — компактный JSON `action_attrs`.
Пример — `examples/valid/route.ics`. Комбинация с `--ndjson` запрещена
(код возврата `2`).
