# Формат вывода

## Событие

```json
{"time": "2026-01-10T06:00:00", "action": "depart", "point": "DEPOT", "point_attrs": {}, "action_attrs": {}}
```

- `time` — строка ISO8601 `YYYY-MM-DDTHH:MM:SS[.mmm][Z|±HH:MM]`; зона
  — офсет `start` окна (`Z`/±HH:MM` — с суффиксом); при наивном `start` —
  зона `timezone` файла, иначе — без. При `start = "+1d"` (дельта, зоны нет)
  — наивное или зона файла. `end` с другим офсетом влияет только на свой
  инстант, зону не меняет.
- Зона `time` одной таблицей (`effective = win_zone.or(file_zone)`,
  проверено исполнением на движке):

  | файл \ окно | наивный старт | старт `Z` | старт `+HH:MM` |
  |---|---|---|---|
  | наивный файл | наивно | `Z` | `+HH:MM` окна |
  | файл `timezone = "Z"` | `Z` | `Z` | `+HH:MM` окна |
  | файл `timezone = "+HH:MM"` | `+HH:MM` файла | `Z` | `+HH:MM` окна |

  Суффикс — только представление (`effective = win_zone.or(file_zone)`),
  а инстанты зависят от кадра (см. [семантику](semantics.md),
  проверено исполнением на движке):

  | файл \ окно | наивный старт | старт `Z` | старт `+HH:MM` |
  |---|---|---|---|
  | наивный файл | наивно, стены как в файле | `Z`, стены как в файле | `+HH:MM` окна, стены как в файле |
  | файл `timezone = "Z"` | `Z` | `Z` | `+HH:MM` окна |
  | файл `timezone = "+HH:MM"` | `+HH:MM` файла | `Z` | `+HH:MM` окна |

  Наивный файл + aware-окно — наследование кадра: стены стоят
  (`06:00` остаётся `06:00` в зоне окна, инстанты = стена − зона окна),
  а не сдвиг на офсет. Наивное ≡ UTC численно только при наивном окне.
  Aware-литералы файла абсолютны всегда.
- `action` — имя из `actions` точки. `point` — имя точки (`IDENT` исходника).
- `point_attrs` — копия атрибутов точки `attrs`; при отсутствии — пустой `{}`.
- `action_attrs` — вычисленные атрибуты действия строки; при отсутствии — `{}`.
- Порядок событий: `(time, k, порядок объявления)`, где `k` — номер экземпляра
  корневого цикла. Совпавшие события сохраняются, схлопывания нет.

## Объект команды run

```json
{"schedule": "Автобусный парк", "start": "...", "end": "...", "events": []}
```

Поля `start`/`end` повторяют аргументы CLI. Машиночитаемая схема —
[output.schema.json](../schemas/output.schema.json) (draft 2020-12):
все `.expected.json` примеров ей соответствуют.

## Объект команды next

Объект `schedule,from,within,events`: `from` — разрешённая ISO-строка,
`within` — миллисекунды числом. Флаг `--ndjson` выводит по событию на строку.

## Календарь ICS

Флаг `--format ics` возвращает календарь RFC 5545 вместо JSON: заголовок
`VCALENDAR`, каждое событие — `VEVENT` без `DTEND` (события мгновенны).
Соответствие полей: `UID` — детерминированный (хеш расписания, времени,
действия, точки и порядкового номера); `DTSTAMP` — момент формирования;
`DTSTART` — aware-окно: время в UTC с `Z`, naive-окно: плавающее время без `Z`;
`SUMMARY` — `action @ point`; `DESCRIPTION` — компактный JSON `action_attrs`.
Пример — `examples/valid/route.ics`. Комбинация с `--ndjson` запрещена
(код возврата `2`).
