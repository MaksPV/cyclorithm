# CLI

```text
usage:
  cyclo run FILE|- --start DATETIME --end DATETIME [--ndjson]
  cyclo next FILE|- [--from DATETIME] [--within DURATION] [-n K] [--ndjson]
  cyclo check FILE|-
  cyclo --version
  cyclo --help
```

- `run` возвращает события окна `[start, end)`. Если `end <= start`,
  список `events` будет пуст, а код возврата равен `0`.
- `next` возвращает первые `K` событий окна `[from, from + within)`.
  По умолчанию `from` — текущий момент с системным смещением от UTC,
  `within` — `366d`, `-n` — `1`.
- `check` проверяет программу без расчёта событий. При успехе команда
  печатает `ok` и возвращает код `0`.
- Вместо имени файла можно передать `-` и подать программу на стандартный
  ввод. В этом случае пути в директивах `use` отсчитываются от текущего
  каталога.
- `--ndjson` выводит по одному событию на строку.

## Даты и длительности {#dates-and-durations}

Полный формат даты — `YYYY-MM-DDTHH:MM:SS[.mmm][Z|±HH:MM]`. В аргументах
команд также можно указать только дату (`YYYY-MM-DD`, то есть полночь)
или дату и время до минут (`YYYY-MM-DDTHH:MM`, то есть с нулём секунд).
Чтобы добавить смещение, используйте полный формат. В поле `start_time`
программы всегда требуется полный формат. Вместо имён часовых поясов
указывайте фиксированное смещение, например `+03:00`.

Запись `+DURATION`, например `+1d`, означает смещение от опорного момента.
Для `--start` и `--from` это текущий момент с системным смещением от UTC.
Для `--end` опорный момент задаёт `--start`. Аргумент `--within` принимает
длительность, например `2h30m`. Целое число без единицы измерения задаёт
миллисекунды.

Время событий в выводе записывается со смещением `--start` или `--from`.
Если его нет, используется `timezone` программы. Если смещение нигде
не задано, время выводится без суффикса. Смещение `--end` влияет только
на момент окончания окна. [Подробнее о часовых поясах](semantics.md#time-zones).

## Коды возврата {#exit-codes}

- `0` — успех.
- `1` — ошибка ввода, разбора или проверки программы. Сообщение выводится
  в стандартный поток ошибок (stderr), стандартный вывод (stdout) пуст.
  Например, если файл нельзя прочитать, команда сообщает `cannot read 'FILE': …`.
- `2` — неверные аргументы. Подсказка по запуску выводится в stderr.
