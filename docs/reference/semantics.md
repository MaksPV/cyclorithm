# Семантика

Как циклы разворачиваются в события.

## Часовые пояса

!!! danger "Переходы DST не поддерживаются"
    Движок не знает летнего/зимнего времени: сутки всегда ровно 24 часа,
    офсеты постоянны. Зоны с переходами (IANA-имена вроде `Europe/Berlin`)
    отклоняются ошибкой `invalid-timezone`; правильное DST — в [todo](../todo.md).

`timezone` расписания (опционально) — только `Z` или числовой `±HH:MM`.
Наивные литералы файла (`start_time`) интерпретируются в кадре
`file_zone.or(query_zone)`: зона файла, иначе — зона окна (`start`/`from`),
иначе — 1:1 как написано. Город пишут в файле один раз — дальше расписание
смотрят из любой точки земли: файл абсолютен, зона окна влияет только
на подписи. Без города в файле наивное читается в городе, из которого
спрашивают: стены стоят, инстанты = стена − зона окна.
Aware-литералы с собственным суффиксом — абсолютны всегда.
Окно вывода форматируется в зоне `start`/`from`,
иначе — в зоне файла, иначе — наивно. Сравнение дат — по абсолютным мс.

Граница модели: календарные встроенные (`hour`, `dow`, `morning`, `evening`,
`datestr`, …) считают от абсолютных миллисекунд и кадру не подчиняются —
как и раньше для файлов с объявленным `timezone`. Пример: наивный `route.cyclo`
с окном `09:00+03:00` держит стены (06:00, 10:00, 14:00 — всего 14 событий),
но 18:00-рейс пропадает: `commute(at)` видит 15:00Z, а не московский вечер.

## Решётка корневого цикла

Корневой цикл задаёт бесконечную решётку стартов: якорь `start_time`
(с учётом `timezone` файла), период `duration`.

$$
T(k) = T_0 + k \cdot P, \quad k = 0, 1, 2, \dots
$$

Движок строит только старты, чьи события могут попасть в окно запроса;
в вывод идут события со временем в `[start, end)`. Окно 10.01–11.01 (суббота)
пересекает решётку маршрута в старте `k = 9` (10.01 00:00): работают рейсы
6:00 и 12:00 — всего 8 событий, будние ветки молчат.

## Строки и вложенность

Строка выполняется в момент «старт объемлющего цикла плюс смещение».
Смещения накапливаются вниз по вложенности: вызов `CITY_ROUTE` на `6h`,
внутри строка на `40m` — событие в 6:40 (`arrive`, `AIRPORT`).

Вызов действия даёт событие в момент строки. Пропуск родителя (ложное
условие) подавляет потомков.

## Границы (`overruns`)

Фактическая длительность цикла — самый поздний конец его строк:

$$
actual(C) = \max_i (o_i + d(X_i))
$$

Она обязана умещаться в объявленную: завершение ровно в границу допустимо,
выход — ошибка. Цикл `C1` длительностью 1h вызывает на `40m` цикл `C2`
длительностью 40m — конец на `40m + 40m = 80m` вылезает на 20m:

```cyclo
cycle C1 duration = 1h {
  40m: C2();  // конец на 80m — за границей
}

cycle C2 duration = 40m {
  0m: DEPOT.depart();
  40m: DEPOT.arrive();
}
```

```text
cycle 'C2' overruns 'C1' by 20m (80m > 60m)
```

Цепочки, пересекающие границу периода корневого цикла, запрещены; для них
выбирается больший `duration` или сдвинутый `start_time`.

## Повторы

Про `repeat` и `fill` — в [концептах](concepts.md). Здесь формальные
детали: горизонт `fill` — конец объемлющего цикла, граница включительная
(`старт + duration ≤ горизонт`); `fill X()` эквивалентен
`fill until <конец родителя> X()`; влезло ноль — ноль событий, это не ошибка.

`fill gaps X [until T]` упаковывает экземпляры `X` в свободные отрезки
окна `[o, h)`, где `o` — эффективное смещение строки, `h` — горизонт
(по умолчанию конец родителя, `until T` и `until -T` — как у `fill`).
Занятость — отрезки `[o_i, o_i + n_i·d_i)` обычных строк (по объявленным
длительностям, все условия считаются истинными). В каждом свободном
отрезке слева направо ставится `⌊len / d⌋` экземпляров встык; остаток
короче `d` пропускается. Filler-ы идут в порядке объявления, и каждый
видит занятость обычных строк и предыдущих filler-ов. `o > h` — окно
пустое и это ошибка. Условие на `fill gaps` проверяется на каждый
экземпляр в его старте; влезло ноль — ноль событий, это не ошибка.

## Разворот циклов

`cycle BACK reverse FWD;` разворачивается в обычный цикл до всех проверок:
смещения зеркалятся относительно длительности (`o' = duration − o`
от эффективного смещения — минус уже разрешён), вызовы, условия, повторы,
параметры и длительность наследуются как есть. Порядок строк — порядок
объявления источника.

Зеркало корректно ложится, когда плечи кончаются на `duration`: крайние
строки `0 ↔ duration` меняются местами. Середина с асимметричными плечами
правится руками отдельным явным циклом. Проверки идут на результате общим
порядком (`cycle-overruns` и остальные): вылезшее за длительность зеркало —
ошибка. Цепочки запрещены — источник обязан быть явным циклом
(иначе `recursive`); рутина или точка как источник — `wrong-kind`,
нет имени — `unknown-cycle`.

## Условия и момент строки

Момент строки `at` — абсолютное время строки. В телах объявлений `fun`/`pred`
`at` означает время места вызова: предикат ниже в строке `[commute(at)] 18h`
вычисляется для момента строки — старта плюс 18h.

```cyclo
root_cycle start_time = "2026-01-09T02:00:00", duration = 24h {
  [commute(at)] 18h: CITY_ROUTE();  // сработает в 20:00, а не в 18:00
}
```

Смещение — не время суток: при старте в 02:00 строка стреляет в 20:00,
при старте в полночь та же строка стреляла бы в 18:00. Условие уже решает
по готовому моменту.

Статический расчёт фактической длительности и проверка границ идут
в предположении истинности всех условий.

## Параметры и данные

Аргументы вызова вычисляются в момент строки — и текут вниз по цепочке
вызовов вместе с окружением. Область видимости динамическая: вызванный цикл
видит параметры вызывающего, даже если своих у него нет.

```cyclo
root_cycle start_time = "2026-09-07T00:00:00", duration = 24h {
  9h: LESSON({"subject": "БЖД"});
}
```

Вызов на `9h`, внутри два смещения `0m`: `LESSON` зовёт безаргументный
`INNER`, тот звонит — и `subj` на месте, хотя у `INNER` параметров нет:

```cyclo
cycle LESSON(subj) duration = 1h35m {
  0m: INNER();
}

cycle INNER duration = 10m {
  0m: BELL.ring() {"subject": subj.subject};
}
```

Событие в 9:00 несёт `{"subject": "БЖД"}`: время — из строки корня, словарь —
из вызова, доехал через голову `INNER`.

Три запрета напоследок. Параметр перекрывает `const`/`fun`/`pred` с тем же
именем. Имя константы-данных прямо в условии запрещено (`unknown-name`) — данные
входят в условие только через параметр. Табличный параметр рутины в условиях
и атрибутах действия невидим (`unknown-name`).

## Таблицы времени и рутины

Вызов `ИМЯ(ТАБЛИЦА, …)` заменяет метки тела смещениями таблицы, вызовы
таблицы добавляются после строк тела; длительность вызова равна длительности
таблицы. Рутина ниже на таблице `SHORT_DAY` даёт звонки в 9:00 и 10:30:

```cyclo
time_const SHORT_DAY duration = 14h35m {
  1st: 9h;
  2nd: 10h30m;
}

routine MONDAY(TC) {
  1st: BELL.ring();
  2nd: BELL.ring();
}
```

```cyclo
0h: MONDAY(SHORT_DAY);  // 1st → 9h, 2nd → 10h30m
```

Имя табличного параметра любое — `TC` лишь соглашение: движок смотрит
на позицию (первый параметр), а не на имя.

Метки, которой нет в таблице, — ошибка. Рутина требует `4th`, в таблице его
нет:

```cyclo
routine WED(TC) {
  4th: BELL.ring();
}
```

```text
unknown slot '4th'
```

Таблица обязана покрывать все метки тела — сокращённый день без нужной метки
ломает вызов, а не пропускает строку молча.

Тело проверяется в длительности каждой таблицы, с которой рутина вызывается;
вина границ и повторов ложится на рутину. Рутина без вызовов — только статическая
проверка имён и условий: покрытие проверить не на чем.
