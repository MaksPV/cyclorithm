# Семантика

Как циклы разворачиваются в события.

## Часовые пояса {#time-zones}

В `timezone` можно указать `Z` (UTC) или фиксированное смещение от UTC
в формате `±HH:MM`. Имена часовых поясов, например `Europe/Berlin`,
возвращают ошибку `invalid-timezone`. Все сутки длятся ровно 24 часа.
Поддержка часовых поясов IANA и переходов на летнее время описана в [планах](../todo.md#iana-and-dst).

Если у даты в файле есть суффикс `Z` или `±HH:MM`, он задаёт точный момент.
Дату без суффикса движок интерпретирует в зоне расписания, если задана
`timezone`, или в зоне начала окна (`start` или `from`). Если смещение
отсутствует в обоих местах, движок использует дату как записано и выводит
время без суффикса.

Например, `06:00` в файле без `timezone` при запросе с началом окна
в 09:00 со смещением `+03:00` означает 06:00 по времени этого окна, то есть 03:00 UTC.
Если в файле задана `timezone`, изменение зоны окна не меняет момент
запуска. Оно меняет только то, как время события записано в выводе.

Вывод использует смещение начала окна или, если его нет, `timezone`
расписания. Для относительного начала окна (`+DURATION`) и для `next`
без `--from` берётся текущее смещение системной зоны.

Календарные функции, например `hour`, `dow` и `datestr`, используют
местное время расчёта (`at.wall`): время в зоне расписания или, если она
не задана, в зоне начала окна. То же местное время
используется при сравнении `at` с датой в строке, например
`at >= "2026-01-10"`.

## Решётка корневого цикла

Корневой цикл задаёт бесконечную решётку стартов: якорь `start_time`
(с учётом `timezone` файла), период `duration`.

$$
T(k) = T_0 + k \cdot P, \quad k = 0, 1, 2, \dots
$$

Движок строит только старты, чьи события могут попасть в окно запроса;
в вывод идут события со временем в `[start, end)`. Окно 10.01–11.01 (суббота)
пересекает решётку маршрута в старте `k = 9` (10.01 00:00): работают рейсы
6:00 и 12:00 — всего 8 событий, будние ветки молчат.

## Строки и вложенность

Смещение строки отсчитывается от начала текущего цикла. Если `CITY_ROUTE`
запускается в 06:00, его строка `40m: AIRPORT.arrive();` даёт событие в 06:40.

Действие точки создаёт событие. Если условие вызова цикла ложно,
все строки этого запуска пропускаются.

## Метки запуска, зависимости и курсор {#launch-labels}

Метка запуска (`as`) даёт имя конкретному запуску цикла:

```cyclo
0h: WARMUP() as W1;
after W1: PRODUCTION();
```

- `after W1:` и `until W1:` задают момент окончания запуска `W1`.
- `at W1:` задаёт момент его начала.
- `start(W1)` и `end(W1)` принимают по одной метке и возвращают начало
  и конец запуска соответственно.
- `max(...)` и `min(...)` принимают один или несколько аргументов. Длительность
  отсчитывается от начала текущего цикла. Метка без `start()` или `end()`
  означает время окончания запуска. Если имя метки совпадает с записью
  длительности, например `1ms`, используйте `start(1ms)` или `end(1ms)`.
  В `max` и `min` запись `1ms` без вызова функции означает длительность.

Курсор хранит самое позднее время окончания уже выполненных строк тела
текущего цикла. Изначально он указывает на начало цикла. Строка с `+:`
выполняется в момент, на который указывает курсор, а с `+10m:` — на 10 минут
позже. У каждого экземпляра цикла свои курсор и метки. Строка может
ссылаться на метки, объявленные выше в теле того же цикла. Если строка
с меткой запускает цикл несколько раз, метка обозначает последний
состоявшийся запуск.

Строка, пропущенная из-за ложного условия, не сдвигает курсор:

```cyclo
[workday(at)] +0m: LUNCH();
+30m: TEA();
```

В выходные `LUNCH` пропускается. `TEA` запускается через 30 минут после
того момента, когда мог бы начаться `LUNCH`. Если помеченный запуск
пропущен, его метка недоступна. Строки, которые зависят от неё напрямую
или через другие запуски, тоже пропускаются без сдвига курсора.

Для строки `fill gaps` и тела исходного цикла в объявлении `reverse`
допустимы только абсолютные смещения. В рутинах можно указывать смещения
и метки слотов таблицы.

## Границы (`overruns`)

Фактическая длительность цикла — самый поздний конец его строк:

$$
actual(C) = \max_i (o_i + d(X_i))
$$

Каждый вызов должен завершиться к концу текущего цикла. В примере часовой
цикл `C1` вызывает `C2` через 40 минут после своего начала. Поскольку
`C2` длится 40 минут, он заканчивается на 20 минут позже `C1`:

```cyclo
cycle C1 duration = 1h {
  40m: C2();  // конец на 80m — за границей
}

cycle C2 duration = 40m {
  0m: DEPOT.depart();
  40m: DEPOT.arrive();
}
```

```text
cycle 'C2' overruns 'C1' by 20m (80m > 60m)
```

Цепочки, пересекающие границу периода корневого цикла, запрещены; для них
выбирается больший `duration` или сдвинутый `start_time`.

## Повторы {#repeats}

`fill` размещает столько полных запусков подряд, сколько помещается до
границы: время начала запуска плюс его длительность должно быть меньше
или равно границе. Без `until` границей служит конец текущего цикла.
Если не помещается ни один запуск, команда не создаёт событий для строки.

`fill gaps [pack DIR] [until T] X()` размещает запуски `X` в свободных
отрезках окна `[o, h)`. Здесь `o` — смещение строки, а `h` — граница
`until` или конец текущего цикла. Если `until` задан и `o > h`,
возникает ошибка `until-out-of-bounds`.

Запланированные запуски обычной строки занимают интервал
`[o_i, o_i + n_i·d_i)`, где `n_i` — число запусков, а `d_i` —
объявленная длительность вызова. При расчёте занятости условия строк
считаются истинными. Строки с динамическими моментами должны стоять выше
первой добивки в том же цикле. Их интервалы вычисляются при расчёте
событий. Если зависимость не разрешилась, строка не занимает интервал.

В свободном отрезке `[a, b)` длиной `len = b − a` помещается
`n = ⌊len / d⌋` полных запусков длительностью `d`. Они идут подряд,
а начало первого запуска задаёт `pack`:

- `pack left` (по умолчанию) начинает запуски в `a`.
- `pack right` начинает запуски в `b − n·d`.
- `pack center` начинает запуски в `a + ⌊(len − n·d) / 2⌋`.

Каждая строка `fill gaps` учитывает интервалы, занятые предыдущими
добивками. В рутине занятость включает интервалы вызовов из таблицы
времени, заданных через `->`. Условие проверяется отдельно для каждого
запуска в момент его начала. Если условие ложно, запуск пропускается.

## Разворот циклов {#reverse-cycles}

`cycle BACK reverse FWD;` разворачивается в обычный цикл до всех проверок:
смещения зеркалятся относительно длительности (`o' = duration − o`
от эффективного смещения — минус уже разрешён), вызовы, условия, повторы,
параметры и длительность наследуются как есть. Порядок строк — порядок
объявления источника.

Строки на отметках `0` и `duration` меняются местами. Если для
обратного маршрута нужны другие интервалы, опишите его отдельным циклом.
К развёрнутому циклу применяются обычные проверки, включая
`cycle-overruns`. Источник должен быть циклом с явно заданным телом.
Ссылка на другой `reverse` даёт `recursive`, на точку или рутину —
`wrong-kind`, на отсутствующее имя — `unknown-cycle`.

## Условия и момент строки {#conditions-and-time}

Момент строки `at` — словарь с тремя полями:

- `abs` — абсолютное время в миллисекундах с начала эпохи Unix.
- `zone` — смещение зоны расчёта от UTC в миллисекундах.
- `wall` — местное время в той же шкале, то есть `abs + zone`. Без
  смещения `wall` и `abs` равны.

Для арифметики и сравнения с числами используйте поля словаря, например
`at.wall`. Использование самого словаря в такой операции вызывает
`type-mismatch`. В теле `fun` или `pred` значение `at` соответствует
моменту строки, из которой вызвана функция или предикат.

```cyclo
root_cycle start_time = "2026-01-09T02:00:00", duration = 24h {
  [commute(at)] 18h: CITY_ROUTE();  // сработает в 20:00, а не в 18:00
}
```

При старте цикла в 02:00 условие строки со смещением `18h` проверяется
для 20:00. При старте в полночь оно проверяется для 18:00.

## Контекст экземпляра `here`

Словарь `here` содержит контекст текущего экземпляра цикла или рутины.
Он доступен в условиях строк и в атрибутах действий. Имена `here` и `at`
зарезервированы (`reserved-name`). Чтобы построить условие на основе
`here`, обращайтесь к его полям. Сам словарь в роли условия даёт
`type-mismatch`.

Ключи верхнего уровня:

| Ключ | Что лежит |
|------|-----------|
| `stack` | Путь вызовов от корня до текущего экземпляра (массив кадров) |
| `events` | Запланированные вызовы и действия текущего экземпляра со статусом `enabled` |
| `enabled_events` | Выполненные вызовы и действия (`event.enabled == true`) |
| `disabled_events` | Пропущенные вызовы и действия (`event.enabled == false`) |

### Стек `stack`

Кадр содержит имя вызова (`name`) и, если есть параметры, словарь
`params` со значениями по именам параметров. У `root_cycle` параметров
нет. Для табличного параметра рутины (`TC`) словарь хранит длительность
таблицы (`duration`) и смещения её меток (`labels`) в миллисекундах.

`len(here.stack)` возвращает глубину вложенности. Текущий вызов доступен
по индексу `-1`, корневой цикл — по индексу `0`:

```cyclo
here.stack[-1].params.subj.teacher
here.stack[-1].params.TC.labels.first
here.stack[0].name  // всегда "root_cycle"
```

### Кандидаты `events`

Кандидат — запись о вызове или действии. Она содержит `event` и одно из полей `point` или `cycle`.
Действие точки даёт `point`, вызов цикла/рутины — `cycle`:

| Ключ | Состав |
|------|--------|
| `point` | `{name, actions, attrs}` — имя точки, её действия, атрибуты |
| `cycle` (цикл) | `{name, duration, params}` — имя, длительность в мс, разрешённые аргументы |
| `cycle` (рутина) | `{name, params, labels}` — имя, `TC` + данные, метки таблицы в мс |
| `event` | `{action?, offset, label?, at, enabled}` — имя действия точки, смещение от начала текущего экземпляра в миллисекундах, метка слота рутины, момент `{wall, abs, zone}` и признак выполнения |

Если поле `point`, `cycle`, `action` или `label` неприменимо, соответствующего
ключа нет. Обращение к нему даёт `unknown-field`. Индекс за пределами
массива даёт `index-out-of-bounds`. Для пропущенного вызова аргументы не
вычисляются. Его `params` пуст, а у рутины содержит только описание таблицы.

### Снимки

Условие строки видит кандидатов, уже обработанных в текущем экземпляре.
Вызовы слотов `->` видят результаты обработки всего тела рутины:

```cyclo
[workday(at) and len(here.enabled_events) > 0] lunch: 12h -> LUNCH();
```

В этом примере обед добавляется в будни, если при обработке тела рутины
выполнилась хотя бы одна строка. В атрибутах действия `here` уже содержит
запись об этом действии. Выражение `{"snap": here}` сохраняет копию словаря
на момент выполнения строки.

### Пример целиком

Программа (понедельник 07.09.2026, в `LESSON` одна строка отключена):

```cyclo
const SUBJ = {"name": "БЖД", "teacher": "Иванов"};
time_const DAY duration = 2h {
  first: 0m;
  second: 1h;
}
schedule "Расписание" {
  point BELL { actions = [ring]; }
  cycle LESSON(subj) duration = 1h {
    [false] 0m: BELL.ring();
    30m: BELL.ring() {"snap": here};
  }
  routine MONDAY(TC, subj) {
    first: LESSON(subj);
    second: BELL.ring() {"snap": here};
  }
  root_cycle start_time = "2026-09-07T00:00:00", duration = 24h {
    [dow(at) == mon] 0h: MONDAY(DAY, SUBJ);
  }
}
```

В событии `LESSON` в 00:30 копия `here` содержит три кадра стека.
В `events` две записи, в том числе пропущенное действие с
`enabled: false`. Поля `enabled_events` и `disabled_events` содержат
записи из того же списка, отобранные по признаку выполнения:

```json
{"stack": [{"name": "root_cycle"},
  {"name": "MONDAY", "params": {"TC": {"duration": 7200000,
    "labels": {"first": 0, "second": 3600000}},
    "subj": {"name": "БЖД", "teacher": "Иванов"}}},
  {"name": "LESSON", "params": {"subj": {"name": "БЖД", "teacher": "Иванов"}}}],
 "events": [
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 0,
    "at": {"wall": 1788739200000, "abs": 1788739200000, "zone": 0},
    "enabled": false}},
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 1800000,
    "at": {"wall": 1788741000000, "abs": 1788741000000, "zone": 0},
    "enabled": true}}],
 "enabled_events": [
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 1800000,
    "at": {"wall": 1788741000000, "abs": 1788741000000, "zone": 0},
    "enabled": true}}],
 "disabled_events": [
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 0,
    "at": {"wall": 1788739200000, "abs": 1788739200000, "zone": 0},
    "enabled": false}}]}
```

В событии `MONDAY` в 01:00 копия `here` содержит вызов `LESSON`.
В поле `cycle` записаны длительность и аргументы, а в `event.label` —
метка слота. Записи о действиях точки не содержат поля `cycle`:

```json
{"cycle": {"name": "LESSON", "duration": 3600000,
   "params": {"subj": {"name": "БЖД", "teacher": "Иванов"}}},
 "event": {"offset": 0, "label": "first",
  "at": {"wall": 1788739200000, "abs": 1788739200000, "zone": 0},
  "enabled": true}}
```

Статический расчёт фактической длительности и проверка границ идут
в предположении истинности всех условий.

## Параметры и данные

Аргументы вычисляются для момента вызова. Область видимости динамическая:
вызванный цикл видит параметры вызывающего цикла, даже если у него самого
нет параметров.

```cyclo
root_cycle start_time = "2026-09-07T00:00:00", duration = 24h {
  9h: LESSON({"subject": "БЖД"});
}
```

`LESSON` вызывает `INNER` без аргументов. Действие в теле `INNER`
использует параметр `subj` из `LESSON`:

```cyclo
cycle LESSON(subj) duration = 1h35m {
  0m: INNER();
}

cycle INNER duration = 10m {
  0m: BELL.ring() {"subject": subj.subject};
}
```

В 09:00 создаётся событие с атрибутом `{"subject": "БЖД"}`.

Параметр перекрывает одноимённое объявление `const`, `fun` или `pred`. Имя константы-данных прямо в условии запрещено (`unknown-name`) — данные
входят в условие только через параметр. Табличный параметр рутины в условиях
и атрибутах действия невидим (`unknown-name`).

## Таблицы времени и рутины

Вызов `ИМЯ(ТАБЛИЦА, …)` заменяет метки тела смещениями таблицы, вызовы
таблицы добавляются после строк тела; длительность вызова равна длительности
таблицы. Рутина ниже на таблице `SHORT_DAY` даёт звонки в 9:00 и 10:30:

Смещение слота должно лежать от начала до конца таблицы включительно.
Отрицательное смещение в теле рутины отсчитывается от конца используемой
таблицы. Например, `-30m:` в рутине с двухчасовой таблицей соответствует
смещению на 1 час 30 минут от начала вызова.

```cyclo
time_const SHORT_DAY duration = 14h35m {
  1st: 9h;
  2nd: 10h30m;
}

routine MONDAY(TC) {
  1st: BELL.ring();
  2nd: BELL.ring();
}
```

```cyclo
0h: MONDAY(SHORT_DAY);  // 1st → 9h, 2nd → 10h30m
```

Имя табличного параметра любое — `TC` лишь соглашение: движок смотрит
на позицию (первый параметр), а не на имя.

Если в таблице нет метки, указанной в теле рутины, вызов завершается
ошибкой. Например, эта рутина требует метку `4th`:

```cyclo
routine WED(TC) {
  4th: BELL.ring();
}
```

```text
unknown slot '4th'
```

При каждом вызове таблица должна содержать все метки из тела рутины.
Длительность этой таблицы задаёт границы вызова и повторов. Если рутина
нигде не вызывается, движок проверяет только имена и условия.
