# Концепты

Что означает каждая сущность расписания и как она записывается.
Порядок — от простых ячеек к целому файлу. Термины —
в [глоссарии](../glossary.md), полные определения — в [legacy-спеке](spec-legacy.md).

## Точка `point`

Место, где происходят действия: парк, аэропорт, звонок. Самый простой
вариант — только список допустимых действий `actions`:

```text
point DEPOT {
  actions = [depart, arrive];
}
```

Дополнительно точка может нести атрибуты `attrs` — словарь, который
копируется в каждое событие точки:

```text
point BELL {
  actions = [ring];
  attrs = {"building": "Л"};
}
```

Поле `attrs` необязательно: без него `point_attrs` события пустое (`{}`).
С ним каждое событие звонка несёт копию словаря:

```json
{"time": "2026-09-07T09:00:00", "action": "ring", "point": "BELL", "point_attrs": {"building": "Л"}, "action_attrs": {}}
```

Поле `action_attrs` здесь пустое, потому что вызов без атрибутов, —
про них в следующем разделе. Если словарь общий для нескольких точек,
его выносят в `const` и ссылаются именем (`attrs = CORPUS;`).

## Действие `action`

То, что происходит в точке. В выводе — поле `action` события.
Вызывается как `<ТОЧКА>.<действие>()`:

```text
0m: BELL.ring();
```

Вызов может нести атрибуты `{"k": v, …}` — они попадают в событие полем
`action_attrs`:

```text
5m: BELL.ring() {"event": "start"};
```

Блок необязателен: без него `action_attrs` пустое. С ним событие выглядит так:

```json
{"time": "2026-09-07T09:05:00", "action": "ring", "point": "BELL", "point_attrs": {"building": "Л"}, "action_attrs": {"event": "start"}}
```

## Событие `event`

Единица вывода — то, что произошло в конкретный момент. Собирается из пяти
частей: время — момент строки, в который сработал вызов; имя действия и имя
точки — из самого вызова; словарь `point_attrs` пришёл из точки, словарь
`action_attrs` — из вызова. Полный вид из примера `attrs.cyclo`:

```json
{"time": "2026-09-07T09:00:00", "action": "ring", "point": "BELL", "point_attrs": {"building": "Л", "floors": 5}, "action_attrs": {"subject": "БЖД", "type": "лек", "room": "233/А", "event": "start"}}
```

События складываются в массив `events` объекта, который выдаёт программа.
Порядок и форма объекта — в [формате вывода](output.md).

## Вызов `invocation`

То, что стоит справа от двоеточия в строке. Два вида: действие точки даёт
событие, вызов цикла или рутины раскрывается в строки. Все возможные формы:

```text
0m: DEPOT.depart();  // действие точки — даёт событие
5m: DEPOT.depart() {"fuel_used": 25};  // действие с атрибутами
6h: CITY_ROUTE();  // цикл без аргументов
9h: LESSON(LEC);  // цикл с передаваемыми в него данными
9h30m: LESSON({"subject": "САПР"});  // а можно и так
0h: MONDAY(UNIVERSITY_DAY);  // рутина — первый аргумент всегда таблица времени
0h: EXAM(DAY, LEC);  // рутина с таблицей и передаваемыми в него данными
```

## Цикл `cycle`

Именованная цепочка строк. Сама по себе событий не порождает, выполняется
только по вызову. В заголовке — необязательные параметры и длительность
`duration`, в теле — строки `<смещение>: <вызов>;`.

```text
cycle CITY_ROUTE duration = 1h20m {
  0m: DEPOT.depart();
  40m: AIRPORT.arrive();
}
```

Параметры принимают данные вызова и видны в теле цикла:

```text
cycle LESSON(subj) duration = 1h35m {
  0m: BELL.ring() {"subject": subj.subject};
}
```

## Условие и момент строки `at`

В языке реализованы условия. Если оно выполняется, то вызовы выполняются. 
Простейшее — один предикат:

```text
[weekend(at)] 12h: CITY_ROUTE(); // выполняется только по выходным
```

Условия могут комбинируются.

```text
[hour(at) >= 7 and not weekend(at)] 10h: SHUTTLE();
```

Условие вычисляется для момента строки `at` — абсолютного времени строки в мс:
времени старта родительского цикла плюс смещение вызываемой строки.

## Повтор (`repeat` / `fill`)

Одна строка запускает цикл несколько раз подряд. Сколько раз — задаёт
модификатор между `:` и вызовом:

```text
10h: repeat 2 SHUTTLE();  // ровно два запуска
14h: fill until 15h SHUTTLE();  // пока помещается до 15h
19h: fill SHUTTLE();  // пока помещается до конца цикла
```

`repeat N` — строгий: ровно `N` запусков, невместившаяся цепочка — ошибка.
`fill` — мягкий: лишнее молча отбрасывается. Горизонт `until T` считается
от старта объемлющего цикла, а не от строки.

Условие строки проверяется для каждого запуска отдельно. Цикл `SHUTTLE` имеет длительность
20 минут, запуски стартуют в 10:30, 10:50 и 11:10 — третий не подходит
под условие и выпадает, первые два стоят на местах:

```text
[hour(at) < 11] 10h30m: repeat 3 SHUTTLE();
```

```text
10:30 — рейс есть
10:50 — рейс есть
11:10 — рейса нет
```

## Таблица времени и рутина `time_const` / `routine`

Пары идут в одно и то же время всю неделю. Без таблицы время каждой пары
пришлось бы писать в каждом дне; с таблицей слоты объявляются один раз,
а дни ссылаются метками:

```text
time_const UNIVERSITY_DAY duration = 21h35m {
  1st: 9h;
  2nd: 10h45m;
}
```

- Объявление верхнего уровня, как `const`/`fun`/`pred`.
- Импортируется через `use`.
- Каждая строка обязана иметь метку.

Строка таблицы может нести вызов со стрелкой `->` — фиксированное событие
дня, объявленное один раз на таблицу, а не на каждый день. Такая строка
выполняется при каждом применении таблицы, может иметь собственное условие:

```text
time_const UNIVERSITY_DAY duration = 21h35m {
  [workday(at)] lunch: 12h20m -> LUNCH();
}
```

День на метках — рутина, шаблон дня. Тело записывает метки вместо смещений,
первый параметр — всегда таблица времени, остальные — данные, как у цикла:

```text
routine MONDAY(TC) {
  1st: LESSON(BJD_LECTURE);
}
```

Вызов `MONDAY(UNIVERSITY_DAY)` подставляет смещения таблицы: метка `1st`
превращается в `9h`, строки таблицы со стрелкой добавляются после строк тела.

Смена таблицы сдвигает все дни сразу: сокращённый день — та же рутина,
другая таблица. Одна строка вместо переписанного дня, пары едут по новой
сетке — 9:00 и 10:30:

```text
time_const SHORT_DAY duration = 14h35m {
  1st: 9h;
  2nd: 10h30m;
}
```

## Корневой цикл `root_cycle`

Задаёт решётку стартов — когда запускаются циклы и одиночные действия.
Ровно один в расписании: пара `start_time` + `duration`, где `duration` —
период решётки. Команда `run` берёт окно `--start/--end` и накладывает
на эту решётку.

```text
root_cycle start_time = "2026-01-09T00:00:00", duration = 24h {
  6h: CITY_ROUTE();
}
```

## Расписание `schedule`

Корень файла. Связывает точки, шаблоны и корневой цикл в одно целое.
Имя попадает в поле `schedule` вывода. Запись: `schedule "Имя" { … }`.

```text
schedule "Автобусный парк" {
  point DEPOT {
    actions = [depart, arrive];
  }
  root_cycle start_time = "2026-01-09T00:00:00", duration = 24h {
    6h: DEPOT.depart();
  }
}
```

## Как связаны

```text
точка point → действия actions (+ атрибуты attrs → point_attrs)
действие action → атрибуты {"k": v} → action_attrs
событие event — оба словаря в момент времени
вызов invocation — действие точки | цикл | рутина
цикл cycle — строки <смещение>: вызов
условие [...] и повтор repeat/fill — модификаторы строк
таблица времени time_const + рутина routine(ТАБЛИЦА) — дни на метках
корневой цикл root_cycle — решётка start_time/duration
расписание schedule — собирает всё в файл
```
