# Концепты

Зачем этот раздел: сначала сущности реального мира, потом их запись в коде.
Полные определения — в [legacy-спеке](spec-legacy.md), здесь — карта.

## Мир расписания

- **schedule** — корневой блок файла. Имя попадает в поле `schedule` вывода.
- **point (точка)** — место: `DEPOT`, `AIRPORT`. Объявляет допустимые **actions**
  и необязательные **attrs** (словарь на каждое событие).
- **action (действие)** — то, что происходит: `depart`, `arrive`, `ring`.
- **cycle (цикл)** — именованная цепочка `<смещение>: <вызов>;` с `duration`.
  Сам ничего не порождает, только вызывается.
- **root_cycle** — корневой цикл: `start_time` + `duration` задают бесконечную
  решётку экземпляров. Его окно пересекают с `--start/--end`.
- **вызов (invocation)** — действие точки `DEPOT.depart()` (+ опциональный блок
  `{k = v}`), вызов цикла `SHUTTLE()` или рутины `MONDAY(DAY)`.
- **событие (event)** — одна запись вывода
  `{time, action, point, point_attrs, action_attrs}`.
- **таблица (`time_const`)** — именованные слоты звонков (`1st: 9h`), живёт до
  `schedule`, импортируется через `use`. Строка с `->` — слот и вызов-пожар.
- **рутина (`routine`)** — шаблон дня: тело на метках вместо смещений,
  вызывается с таблицей `MONDAY(DAY)`.
- **условие** — `[выражение]` перед строкой, считается для времени строки (`at`).
- **повтор** — `repeat N` / `fill [until T]`: цепочка экземпляров вместо одного.

## Как связаны

```text
schedule
├── point → actions (+ attrs → point_attrs)
├── time_const → слоты + пожары ->
├── routine(TABLE) → тело на метках
├── cycle → строки <смещение>: вызов
└── root_cycle → решётка start_time/duration → вызовы → события
```

Детали жизненного цикла вызова — в [семантике](semantics.md),
словарь терминов — в [глоссарии](../glossary.md).
