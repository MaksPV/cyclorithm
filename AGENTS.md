# AGENTS.md — Cyclorithm

## Источник правды
- Канон — `docs/spec.md`. Семантику не дублировать в других файлах: дубли гниют, побеждает спека.
- Пример из §1 — исполняемый контракт: `examples/valid/route.cyclo`, `examples/valid/libs/route_lib.cyclo` и `examples/valid/route.expected.json` обязаны совпадать с ним дословно (проверка — скриптом через `re`+`json`, см. «Как менять спеку»).
- Спека — один файл, пока меньше ~800 строк; дальше сплит по разделам.
- Файлы `описание.md` / `задачи учебные.md` лежат в **родительской** папке (`ScheduleLang/`), это старые размышления, не спека. Не реализовывать по ним.
- Описания вне кода (старые планы в чате) могут противоречить спеке — побеждает спека.
- Зависимые артефакты канона: `examples/` (см. «Примеры»).

## Конвейер (порядок фаз менять нельзя)
1. `parse` — файл → `SourceFile { uses, decls, schedule }` (парсер валидации не делает).
2. `collect_units` — DFS по `use`: системный файл → импорты → программа; путь — от директории импортирующего.
3. `resolve_units` — склейка объявлений (`E04` — только внутри одного файла).
4. Валидация решётки (§5, первая ошибка побеждает): имена (`E04`, `E09`, затем `E01`/`E02`/`E03`) → рекурсия (`E06`) → длительности/повторы/границы (`E05`, `E10`, `E07`) → условия (`E11`, `E12`: сначала объявления, затем строки) → даты (`E08`).
5. `expand` — разворачивание в события, сортировка `(time, k, порядок объявления)`, один JSON в stdout.
- Якоря, которые легко перепутать: `fill until T` — горизонт от старта **родителя**, не от строки; `-0m` ≡ длительность цикла; условие на `repeat`/`fill` проверяется на **каждый экземпляр** в его старте (дыры, не сдвиг); `at` в телах объявлений — время **вызова**; `__`-имена видны только своему юниту (чужое — `E11`).

## Карта модулей (Cargo workspace, edition 2021)
- `crates/cyclorithm-parser` — грамматика (`grammar.pest`) + AST (`lib.rs`: `SourceFile`, `Decl`, `Cond`/`Expr`, фикстура `route_ast`). Решено: парсер на `pest` (EBNF из §3 спеки ложится почти 1:1).
- `crates/cyclorithm-core` — `validate.rs` (коды `E01–E14` из §5), `cond.rs` (объявления, выражения, `resolve_units`), `imports.rs` (`collect_units`, `clean_join`), `std.cyclo` (прелюдия: календарь и словарь, `use` не нужен), `expand.rs` (решётка), `datetime.rs`/`duration.rs`, конструкторы ошибок в `lib.rs` (`Error::eNN_*`).
- `crates/cyclorithm-cli` — бинарь `cyclo` (`run`): читает файл + `use` через `dir_fs` от директории файла; контракт CLI в §1 спеки. Exit-коды: `0` — успех, `1` — ввод/парсинг/валидация (текст в stderr, в stdout ничего), `2` — неверные аргументы (usage в stderr).
- Время внутри — `i64` миллисекунды от unix epoch, наивное (без таймзон); длительности фиксированные (`w=7d`, `d=24h`).

## Тесты (три уровня)
- Unit в крейтах: семантика условий (`cond.rs`), развёртка (`expand.rs` — вход через `setup()` с `Box::leak`, импорты подменяются картой из памяти), AST (`route_ast` обязан зеркалить `route.cyclo` — см. `ast_fixture_covers_spec_example`).
- E2E (`crates/cyclorithm-cli/tests/e2e.rs`): прогон бинаря по каждому `examples/valid/*.cyclo` сверкой с `.expected.json` (файловая система — от директории примера, `use` работает как в проде).
- Негативные: `examples/invalid/bad_*.cyclo` — минимум один файл на код ошибки (`bad_syntax.cyclo` — ошибка парсера без кода).
- Правило: новый код ошибки = пример `bad_eXX.cyclo` + строка в §5 спеки + тест. README раздел ошибок не содержит — его не трогать. `.expected.json` генерировать бинарём, но проверять глазами — не вслепую.

## Как менять спеку
- Код-блок §1, `route.cyclo` и `route.expected.json` — тройное дословное равенство; проверять скриптом (`re`-блоки `text`/`json` vs файлы, JSON — разбором, не строками). Он уже дважды ловил рассинхрон.
- Тексты ошибок в §5 — точные строки из `Error::eNN_*`, сверять `grep` по коду (`E\d+`).
- Открытые решения помечать черновиком прямо в тексте (пример: переполнение арифметики в `E12`).
- Термины §2 — обновлять вместе с фичей (условие, `at`, объявление, `use`, повтор — уже там).

## Git и CI
- Рабочая ветка — `dev` (`main` — стабильная, строгий предок; вливание — fast-forward или merge-PR). PR создавать с `base=dev` через `gh` (авторизация владельца уже настроена).
- Коммиты — по ходу работы, мелкими (владелец любит много коммитов на ветку); пуш и PR (`gh pr create`) — по просьбе («делай», «погнал», «коммит, пуш» и т.п.); мерж PR (`gh pr merge --merge`) — только по явному «чтобы в dev всё было» (дождаться зелёного CI: `gh pr checks`), удаление веток после мержа — не трогать без просьбы.
- Сообщения коммитов — на русском, по содержимому (примеры в `git log`), с суффиксом `, Muse Spark`.
- Терминал неинтерактивный: `git rebase --continue` и подобные — только с `GIT_EDITOR=true` (иначе открывается vim и всё виснет); правку среднего коммита — через `commit --fixup` + `rebase -i --autosquash` с `GIT_SEQUENCE_EDITOR=true`.
- Заглушки — генеральные (`placeholder()`), не проектировать методы/типы вперёд спеки. Проверено на опыте: преждевременные `Event`/`parse()` пришлось откатывать.
- Проверки после правок: `cargo test --workspace` (зелёный), `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets` (без предупреждений). То же гоняет CI (`.github/workflows/ci.yml`: fmt → clippy `-D warnings` → test, на push/PR в `main`/`dev`).

## Примеры
- `examples/valid/*.cyclo` — только исполняемое (у каждого — `.expected.json`); всё подключаемое — только в `examples/valid/libs/` (урок: `route_lib.cyclo` переехал из корня `valid/`).
- `examples/invalid/bad_*.cyclo` — по одному минимальному файлу на код (суффиксы `_neg`, `_until`, `_zero`, `_cycle` и т.п. — вариации того же кода).
- `examples/real/` — живые расписания (`101.cyclo`, `fleet.cyclo` + `fleet_lib.cyclo`): прогонять бинарём и сверять результат глазами при изменении движка.
- Комментарии в контрактных файлах запрещены де-факто: ломают дословность §1.

## Ловушки
- Кириллица-латиница: в истории уже создавалась мусорная папка `cyclритм/` из-за одной кириллической буквы в пути. Пути с `cyclorithm` проверять побуквенно; перед созданием файлов — `ls` родителя.
- Рендер GitHub: math-блоки `$$` только с нулевым отступом (внутри списков не рендерятся) и только ASCII внутри (кириллица в `\text{}` ломает KaTeX).
- `ms` в грамматике — единый юнит, в альтернативе `duration_item` обязан идти раньше `m` (иначе лексер разрежет `1ms`).
- Длительность `0` для `root_cycle` запрещена (деление на ноль в решётке) — это кейс `E05`, не забыть при реализации.
- Порядок/уникальность компонентов длительности (`1h2h`, `30s1d`) — уровень валидации, грамматика их пропускает осознанно.
- Выстраданное: `fill until` от старта родителя — строка после горизонта даёт **ноль** экземпляров, это не баг; тестовый `setup()` без резолва импортов падает `E11` на первом же `use`; `route_ast`-фикстура рассинхронизируется с `route.cyclo` при каждой правке контракта — обновлять вместе; `clean_join` хранит ведущие `..` (чистка путей их не съедает).
