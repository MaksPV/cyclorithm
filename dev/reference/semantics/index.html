    Семантика¶

    Как циклы разворачиваются в события.

    Часовые пояса¶

    Переходы DST не поддерживаются

    Движок не знает летнего/зимнего времени: сутки всегда ровно 24 часа, офсеты постоянны. Зоны с переходами (IANA-имена вроде Europe/Berlin) отклоняются ошибкой invalid-timezone; правильное DST — в todo.

    timezone расписания (опционально) — только Z или числовой ±HH:MM. Наивные литералы файла (start_time) интерпретируются в кадре file_zone.or(query_zone): зона файла, иначе — зона окна (start/from), иначе — 1:1 как написано. Город пишут в файле один раз — дальше расписание смотрят из любой точки земли: файл абсолютен, зона окна влияет только на подписи. Без города в файле наивное читается в городе, из которого спрашивают: стены стоят, инстанты = стена − зона окна. Aware-литералы с собственным суффиксом — абсолютны всегда. Окно вывода форматируется в зоне start/from, иначе — в зоне файла, иначе — наивно. Дефолтное окно (без --from, дельта +DURATION от now) — в системной зоне ОС. Сравнение дат — по абсолютным мс.

    Календарные встроенные (hour, dow, morning, evening, datestr, …) считают по стене кадра (at.wall), поэтому кадру подчиняются: наивный route.cyclo с окном 09:00+03:00 держит стены (06:00, 10:00, 14:00) и 18:00-рейс на месте — commute(at) видит московский вечер, всего 18 событий. Сравнение дат-как-строк (at >= "2026-01-10") — тоже по стене.

    Решётка корневого цикла¶

    Корневой цикл задаёт бесконечную решётку стартов: якорь start_time (с учётом timezone файла), период duration.

    \[ T(k) = T_0 + k \cdot P, \quad k = 0, 1, 2, \dots \]

    Движок строит только старты, чьи события могут попасть в окно запроса; в вывод идут события со временем в [start, end). Окно 10.01–11.01 (суббота) пересекает решётку маршрута в старте k = 9 (10.01 00:00): работают рейсы 6:00 и 12:00 — всего 8 событий, будние ветки молчат.

    Строки и вложенность¶

    Строка выполняется в момент «старт объемлющего цикла плюс смещение». Смещения накапливаются вниз по вложенности: вызов CITY_ROUTE на 6h, внутри строка на 40m — событие в 6:40 (arrive, AIRPORT).

    Вызов действия даёт событие в момент строки. Пропуск родителя (ложное условие) подавляет потомков.

    Границы (overruns)¶

    Фактическая длительность цикла — самый поздний конец его строк:

    \[ actual(C) = \max_i (o_i + d(X_i)) \]

    Она обязана умещаться в объявленную: завершение ровно в границу допустимо, выход — ошибка. Цикл C1 длительностью 1h вызывает на 40m цикл C2 длительностью 40m — конец на 40m + 40m = 80m вылезает на 20m:

    cycle C1 duration = 1h {
  40m: C2();  // конец на 80m — за границей
}

cycle C2 duration = 40m {
  0m: DEPOT.depart();
  40m: DEPOT.arrive();
}

    cycle 'C2' overruns 'C1' by 20m (80m > 60m)

    Цепочки, пересекающие границу периода корневого цикла, запрещены; для них выбирается больший duration или сдвинутый start_time.

    Повторы¶

    Про repeat и fill — в концептах. Здесь формальные детали: горизонт fill — конец объемлющего цикла, граница включительная (старт + duration ≤ горизонт); fill X() эквивалентен fill until <конец родителя> X(); влезло ноль — ноль событий, это не ошибка.

    fill gaps X [pack DIR] [until T] упаковывает экземпляры X в свободные отрезки окна [o, h), где o — эффективное смещение строки, h — горизонт (по умолчанию конец родителя, until T и until -T — как у fill). Занятость — отрезки [o_i, o_i + n_i·d_i) обычных строк (по объявленным длительностям, все условия считаются истинными). В каждом свободном отрезке [a, b) ставится n = ⌊len / d⌋ экземпляров встык; остаток короче d пропускается. Направление упаковки DIR: pack left (default) — старт блока в a; pack right — старт блока в b − n·d; pack center — старт блока в a + (len − n·d) / 2 с округлением сдвига вниз. Filler-ы идут в порядке объявления, и каждый видит занятость обычных строк и предыдущих filler-ов. o > h — окно пустое и это ошибка. Условие на fill gaps проверяется на каждый экземпляр в его старте; влезло ноль — ноль событий, это не ошибка.

    Разворот циклов¶

    cycle BACK reverse FWD; разворачивается в обычный цикл до всех проверок: смещения зеркалятся относительно длительности (o' = duration − o от эффективного смещения — минус уже разрешён), вызовы, условия, повторы, параметры и длительность наследуются как есть. Порядок строк — порядок объявления источника.

    Зеркало корректно ложится, когда плечи кончаются на duration: крайние строки 0 ↔ duration меняются местами. Середина с асимметричными плечами правится руками отдельным явным циклом. Проверки идут на результате общим порядком (cycle-overruns и остальные): вылезшее за длительность зеркало — ошибка. Цепочки запрещены — источник обязан быть явным циклом (иначе recursive); рутина или точка как источник — wrong-kind, нет имени — unknown-cycle.

    Условия и момент строки¶

    Момент строки at — словарь кадра {wall, abs, zone}: wall — стена (представление в зоне кадра file.or(query)), abs — миллисекунды epoch, zone — сдвиг кадра в мс. Инвариант: wall ≡ abs + zone; без зон wall == abs. Доступ — только явный (at.wall, at.abs): голый at в арифметике и сравнениях с числами — type-mismatch. В телах объявлений fun/pred at означает время места вызова: предикат ниже в строке [commute(at)] 18h вычисляется для момента строки — старта плюс 18h.

    root_cycle start_time = "2026-01-09T02:00:00", duration = 24h {
  [commute(at)] 18h: CITY_ROUTE();  // сработает в 20:00, а не в 18:00
}

    Смещение — не время суток: при старте в 02:00 строка стреляет в 20:00, при старте в полночь та же строка стреляла бы в 18:00. Условие уже решает по готовому моменту.

    Контекст инстанции here¶

    Вторая синтетика строк (наряду с at) — словарь инстанции: виден в условиях строк и в блоках действий. Объявлять here нельзя (reserved-name), как и at; голый here в позиции условия — type-mismatch (словарь — не условие).

    Ключи верхнего уровня:

    Ключ Что лежит
    stack Путь вызовов от корня до текущей инстанции (массив кадров)
    events Все кандидаты инстанции с флагом enabled
    enabled_events Те же кандидаты, где event.enabled == true — то, что попадает в timeline
    disabled_events Где event.enabled == false — проверки отсутствия и диагностика

    Стек stack¶

    Кадр — {name} или {name, params} (root_cycle — без параметров). params — формальное имя → разрешённое значение; табличный параметр рутины (TC) — дескриптор {duration, labels} (длительность таблицы и метки в мс). Глубина вложенности — len(here.stack); верх — here.stack[-1], корень — here.stack[0]. Цепочки — обычными точкой и индексом (отрицательный — с конца, как везде):

    here.stack[-1].params.subj.teacher
here.stack[-1].params.TC.labels.first
here.stack[0].name  // всегда "root_cycle"

    Кандидаты events¶

    Кандидат — строка инстанции в конкретном старте: {point?, cycle?, event}. Действие точки даёт point, вызов цикла/рутины — cycle:

    Ключ Состав
    point {name, actions, attrs} — имя точки, её действия, атрибуты
    cycle (цикл) {name, duration, params} — имя, длительность в мс, разрешённые аргументы
    cycle (рутина) {name, params, labels} — имя, TC + данные, метки таблицы в мс
    event {action?, offset, label?, at, enabled} — действие (null у вызовов циклов — ключа нет), смещение в мс от старта инстанции, метка рутины, момент {wall, abs, zone}, флаг

    Отсутствующие point / cycle / action / label — без ключа (у значений нет null): доступ к ним — unknown-field. Индекс вне границ — index-out-of-bounds. Невыполненная строка аргументы не вычисляет: её params пусты (у рутины — только дескриптор TC, таблица — литерал).

    Снимки¶

    Снимок — «на данный момент» в порядке развёртки: условие строки видит кандидатов ранее разобранных строк своей инстанции. Вызовы слотов -> видят итоговый список тела (детерминирован) — так условие отличает пустое тело от полного:

    [workday(at) and len(here.enabled_events) > 0] lunch: 12h -> LUNCH();

    Пустое тело — обеда нет. Блок действий видит here уже с собственным кандидатом, а в action_attrs словарь замораживается копированием: {"snap": here} кладёт мёртвый JSON момента, живых ссылок нет.

    Пример целиком¶

    Программа (понедельник 07.09.2026, в LESSON одна строка отключена):

    const SUBJ = {"name": "БЖД", "teacher": "Иванов"};
time_const DAY duration = 2h {
  first: 0m;
  second: 1h;
}
schedule "Расписание" {
  point BELL { actions = [ring]; }
  cycle LESSON(subj) duration = 1h {
    [false] 0m: BELL.ring();
    30m: BELL.ring() {"snap": here};
  }
  routine MONDAY(TC, subj) {
    first: LESSON(subj);
    second: BELL.ring() {"snap": here};
  }
  root_cycle start_time = "2026-09-07T00:00:00", duration = 24h {
    [dow(at) == mon] 0h: MONDAY(DAY, SUBJ);
  }
}

    Заморозка {"snap": here} внутри LESSON (событие 00:30) — стек глубиной 3, оба кандидата (включая отключённого с enabled: false), геттеры — фильтры того же списка:

    {"stack": [{"name": "root_cycle"},
  {"name": "MONDAY", "params": {"TC": {"duration": 7200000,
    "labels": {"first": 0, "second": 3600000}},
    "subj": {"name": "БЖД", "teacher": "Иванов"}}},
  {"name": "LESSON", "params": {"subj": {"name": "БЖД", "teacher": "Иванов"}}}],
 "events": [
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 0,
    "at": {"wall": 1788739200000, "abs": 1788739200000, "zone": 0},
    "enabled": false}},
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 1800000,
    "at": {"wall": 1788741000000, "abs": 1788741000000, "zone": 0},
    "enabled": true}}],
 "enabled_events": [
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 1800000,
    "at": {"wall": 1788741000000, "abs": 1788741000000, "zone": 0},
    "enabled": true}}],
 "disabled_events": [
  {"point": {"name": "BELL", "actions": ["ring"], "attrs": {}},
   "event": {"action": "ring", "offset": 0,
    "at": {"wall": 1788739200000, "abs": 1788739200000, "zone": 0},
    "enabled": false}}]}

    На уровень выше (заморозка в теле MONDAY, событие 01:00) кандидаты — вызовы: цикл — с duration и params, метка строки — в event.label, действия точки — без cycle:

    {"cycle": {"name": "LESSON", "duration": 3600000,
   "params": {"subj": {"name": "БЖД", "teacher": "Иванов"}}},
 "event": {"offset": 0, "label": "first",
  "at": {"wall": 1788739200000, "abs": 1788739200000, "zone": 0},
  "enabled": true}}

    Статический расчёт фактической длительности и проверка границ идут в предположении истинности всех условий.

    Параметры и данные¶

    Аргументы вызова вычисляются в момент строки — и текут вниз по цепочке вызовов вместе с окружением. Область видимости динамическая: вызванный цикл видит параметры вызывающего, даже если своих у него нет.

    root_cycle start_time = "2026-09-07T00:00:00", duration = 24h {
  9h: LESSON({"subject": "БЖД"});
}

    Вызов на 9h, внутри два смещения 0m: LESSON зовёт безаргументный INNER, тот звонит — и subj на месте, хотя у INNER параметров нет:

    cycle LESSON(subj) duration = 1h35m {
  0m: INNER();
}

cycle INNER duration = 10m {
  0m: BELL.ring() {"subject": subj.subject};
}

    Событие в 9:00 несёт {"subject": "БЖД"}: время — из строки корня, словарь — из вызова, доехал через голову INNER.

    Три запрета напоследок. Параметр перекрывает const/fun/pred с тем же именем. Имя константы-данных прямо в условии запрещено (unknown-name) — данные входят в условие только через параметр. Табличный параметр рутины в условиях и атрибутах действия невидим (unknown-name).

    Таблицы времени и рутины¶

    Вызов ИМЯ(ТАБЛИЦА, …) заменяет метки тела смещениями таблицы, вызовы таблицы добавляются после строк тела; длительность вызова равна длительности таблицы. Рутина ниже на таблице SHORT_DAY даёт звонки в 9:00 и 10:30:

    time_const SHORT_DAY duration = 14h35m {
  1st: 9h;
  2nd: 10h30m;
}

routine MONDAY(TC) {
  1st: BELL.ring();
  2nd: BELL.ring();
}

    0h: MONDAY(SHORT_DAY);  // 1st → 9h, 2nd → 10h30m

    Имя табличного параметра любое — TC лишь соглашение: движок смотрит на позицию (первый параметр), а не на имя.

    Метки, которой нет в таблице, — ошибка. Рутина требует 4th, в таблице его нет:

    routine WED(TC) {
  4th: BELL.ring();
}

    unknown slot '4th'

    Таблица обязана покрывать все метки тела — сокращённый день без нужной метки ломает вызов, а не пропускает строку молча.

    Тело проверяется в длительности каждой таблицы, с которой рутина вызывается; вина границ и повторов ложится на рутину. Рутина без вызовов — только статическая проверка имён и условий: покрытие проверить не на чем.
